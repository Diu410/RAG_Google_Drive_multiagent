# Фортуна

Локальный помощник для работы с документами, папками и кодом через чат.
Генерация и смысловой поиск используют отдельные локальные GGUF-модели через
`llama-server`; обязательной зависимости от Ollama нет.

**Стек:** React, TypeScript, Vite, FastAPI, Tauri 2 / Rust, SQLite и Chroma.

## Возможности

- Чат с историей, потоковыми ответами, отменой и профилями FAST / BALANCED / REASONING.
- Вопросы по рабочей папке или библиотеке документов: RAG, GraphRAG,
  автоматическая мультиагентная редактура, модельная сверка и фрагменты источников.
- Выбор области поиска: вся рабочая папка, подпапка или отдельные файлы.
  Текстовая и векторная индексация, проверка изменений, карта близости документов.
- Поиск файла по описанию с продолжением «открой первый» или «покажи второй документ».
- Загрузка PDF, DOCX, HTML и TXT, импорт папок Google Drive.
- Чтение файлов, поиск с номерами строк, создание текста по источникам,
  точная замена и экспорт в TXT, MD, HTML, DOCX, PDF, CSV и TSV.
  «Сохрани этот ответ в PDF» переносит полный предыдущий ответ чата.
- Репозиторный агент для исследования кода, правок и запуска разрешённых проверок
  с журналом изменений и выводом процессов.
- Голосовой ввод и Live-диалог при установленном распознавании речи.

## Требования

Основной сценарий — **Windows 10/11 и PowerShell**. Для запуска из исходников нужны:

- Python **3.12+** и Node.js **22 или 24** с npm.
- `llama-server` для Windows и две GGUF-модели: чат и embeddings.
- Для desktop-разработки и сборки: Rust с MSVC toolchain, Microsoft C++ Build Tools
  с компонентом **Desktop development with C++**, Windows SDK и WebView2 Runtime.
  См. [требования Tauri для Windows](https://v2.tauri.app/start/prerequisites/#windows).

Сборка llama.cpp должна соответствовать оборудованию: CPU либо CUDA для NVIDIA.
Потребление памяти и скорость зависят от модели, квантования и размера контекста.

## Установка из исходников

Команды выполняются в PowerShell; после клонирования — из корня проекта:

```powershell
git clone https://github.com/Diu410/RAG_Google_Drive_multiagent.git
cd RAG_Google_Drive_multiagent
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r api/requirements.txt
npm ci
npm --prefix frontend ci
```

Активировать `.venv` не требуется. Настройки собраны в
[api/.env.example](api/.env.example): при необходимости создайте по этому образцу
`api/.env`. Не перезаписывайте существующий файл настроек.

### Локальные модели

1. Скачайте подходящий [релиз llama.cpp](https://github.com/ggml-org/llama.cpp/releases).
   Поместите `llama-server.exe` и необходимые DLL того же релиза в `runtime/llama/`.
2. Скачайте GGUF-модели и разместите их по стандартным путям:

| Назначение | Пример модели | Путь для запуска из исходников |
| --- | --- | --- |
| Чат | [Qwen3.5-4B Q4_K_M](https://huggingface.co/lmstudio-community/Qwen3.5-4B-GGUF/tree/main) | `api/models/chat.gguf` |
| Embeddings | [Nomic Embed Text v1.5 GGUF](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5-GGUF) | `api/models/nomic-embed-text.gguf` |

Скачанные файлы можно переименовать в указанные имена либо задать собственные
пути через `LLAMA_MODEL_PATH` и `EMBEDDING_MODEL_PATH`. Относительные пути моделей
считаются от каталога данных приложения. Веса не входят в Git и installer.

Приложение автоматически запускает chat-сервер на `127.0.0.1:8081` и embeddings
на `127.0.0.1:8082`; адреса настраиваются в `.env`. Статус загрузки виден в чате.
Одновременно активна одна chat-модель; её выбор отделён от профиля ответа.
Смена embedding-модели требует перестроения индекса.

## Запуск

### Desktop в режиме разработки

```powershell
npm run desktop:dev
```

Tauri запускает интерфейс и backend из корневой `.venv` самостоятельно.
Отдельно запускать `backend:dev` для этого режима не нужно.

### Web-интерфейс в режиме разработки

В первом терминале:

```powershell
npm run backend:dev
```

Во втором терминале, также из корня проекта:

```powershell
npm run frontend:dev
```

Откройте адрес Vite, напечатанный в терминале. Backend должен работать на
`127.0.0.1:8000` — этот адрес задан в прокси frontend.

## Сборка Windows installer

После установки зависимостей и размещения llama-server:

```powershell
npm run desktop:build
```

Скрипт собирает frontend, упаковывает Python-backend через PyInstaller
(устанавливая его при необходимости), добавляет llama-server и создаёт NSIS
installer в `frontend/src-tauri/target/release/bundle/nsis/`.

После установки запускайте «Фортуну» из меню Start или ярлыка: Python, npm
и отдельный терминал для работы не нужны. GGUF-веса на новом компьютере нужно
разместить отдельно в каталоге данных; требуемый путь показывает статус модели.
Закрытие приложения завершает принадлежащий ему backend и серверы моделей.

## Работа с источниками

Выберите рабочую папку в левой панели. Для подготовки смыслового поиска нажмите
«Индексировать папку» в Workspace. Выбор папки сам по себе не строит векторы;
«Проверить изменения» обновляет сведения о файлах, «Повторить ошибки» — неудачные записи.
Постоянного фонового наблюдения за папкой нет.

Область источников выбирается отдельно от просмотра файлов. Библиотека
загруженных документов и рабочая папка — разные источники. Под ответом можно
посмотреть сохранённые фрагменты; изменившийся файл не подменяет старую цитату.
Карта показывает смысловую близость, а не доказанные отношения между документами.

## Дополнительные возможности

### Голос и Live

Для распознавания установите пакет до запуска или упаковки backend:

```powershell
.venv\Scripts\python.exe -m pip install faster-whisper
```

Модель Whisper загружается при первом использовании; разрешите доступ к микрофону.
CosyVoice настраивается отдельно переменными `COSYVOICE_*` из примера настроек;
при отсутствии настроенного TTS используется системная озвучка интерфейса.

### OCR для сканов PDF

Установите Tesseract с языками `rus` и `eng`, а также Poppler. Если программы
недоступны через PATH, задайте `TESSERACT_CMD` и `POPPLER_PATH`. OCR не гарантирует
безошибочное распознавание; неподдерживаемые документы и превышения лимитов дают ошибки.

### Google Drive

Для запуска из исходников включите Google Drive API в Google Cloud,
создайте OAuth-клиент типа **Desktop app** и сохраните его JSON как
`api/credentials.json`. Выполните авторизацию:

```powershell
.venv\Scripts\python.exe api/gdrive_auth.py
```

Откроется браузер, после входа появится `api/token.json`. Затем передайте ссылку
на папку через окно документов. Для установленного desktop файлы `credentials.json`
и `token.json` должны находиться в его каталоге данных. Доступ запрашивается
только на чтение; автоматической синхронизации с Drive нет.

## Настройки и данные

Образец настроек — [api/.env.example](api/.env.example). Основные параметры:

| Параметр | Назначение |
| --- | --- |
| `LLAMA_MODEL_PATH`, `EMBEDDING_MODEL_PATH` | Пути к GGUF-моделям |
| `LLAMA_SERVER_EXECUTABLE` | Путь к llama-server, если он установлен не в стандартном месте |
| `LLAMA_CONTEXT_SIZE`, `LLAMA_GPU_LAYERS`, `LLAMA_THREADS` | Контекст и распределение ресурсов |
| `ANSWER_REVIEW_MODE` | `contextual` по умолчанию; `strict` — строгая проверка |
| `WHISPER_*`, `COSYVOICE_*` | Распознавание и озвучка речи |

При запуске из исходников данные по умолчанию хранятся в `api/`; другой каталог
задаётся переменной окружения `KONTUR_DATA_DIR` до запуска backend. Установленный
desktop использует `%LOCALAPPDATA%\local.kontur.rag`. Там находятся SQLite,
Chroma, настройки и журналы. Журнал запуска `backend.log` desktop сохраняет
в этом каталоге и в режиме разработки.

Не удаляйте базы, модели, `.env`, credentials и токены при очистке проекта;
перед переносом данных сделайте резервную копию.

## Ограничения и безопасность

- Модель может ошибаться даже при положительной оценке сверки. Контекстная проверка
  рекомендательная: неподтверждённая фраза может остаться с замечанием. Источники
  и статус проверки не гарантируют истинность или полный охват документов.
- Приложение предназначено для личного локального использования, не для публикации
  API в интернет. Локальный API проверяет Host, Origin и токен запуска.
- Явная просьба изменить файл может выполняться без второго подтверждения;
  для предварительного просмотра попросите об этом в запросе. Конвертация
  переносит извлечённый текст, а не исходное оформление и изображения.
- Репозиторные проверки исполняют код проекта с правами пользователя,
  а не в песочнице ОС. Не запускайте их в недоверенных проектах.
- Импорт, извлечение, поиск и генерация ограничены размером и временем.
  Пропуски и незавершённая проверка не считаются успешным полным результатом.

## Если что-то не работает

| Проблема | Что проверить |
| --- | --- |
| Desktop не запускает backend | Детали стартовой ошибки и `backend.log` в каталоге данных desktop |
| Web-интерфейс не видит API | Отдельный backend на `127.0.0.1:8000` |
| Модель не загружается | Пути GGUF, DLL, доступную память, `llama-server.log` и `embedding-server.log` в каталоге данных backend |
| Нет голосового ввода | Установку Whisper и разрешение на микрофон |
| Drive требует авторизацию | Наличие актуальных credentials и токена в каталоге данных выбранного режима |

## Проверки и состав исходников

Доступные проверки из корня проекта:

```powershell
.venv\Scripts\python.exe scripts/check_secrets.py
.venv\Scripts\python.exe -m compileall -q api scripts/check_secrets.py frontend/scripts/backend_entry.py
npm --prefix frontend run build
```

Эти же проверки выполняет [CI](.github/workflows/checks.yml). Они проверяют
секреты по заданным шаблонам, синтаксис Python и сборку TypeScript/Vite,
но не поведение приложения и не качество ответов GGUF.

| Каталог | Содержимое |
| --- | --- |
| [api/](api/) | Backend, поиск, верификация, файловые инструменты и провайдеры моделей |
| [frontend/src/](frontend/src/) | Интерфейс чата и работы с документами |
| [frontend/src-tauri/](frontend/src-tauri/) | Desktop-оболочка и настройки installer |
| [frontend/scripts/](frontend/scripts/) | Запуск и упаковка backend |

В Git хранится рабочий код с конфигурацией и lock-файлами. Документация разработчика,
тестовые наборы, примеры, обучение и изолированные эксперименты намеренно исключены
из текущего дерева; для запуска они не требуются. Пользовательские данные и GGUF
также не публикуются. Удаление из текущего дерева не очищает прежнюю историю Git.
Карта модулей и правила разработки находятся в [AGENTS.md](AGENTS.md).
