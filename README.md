# Фортуна

Фортуна — локальный помощник для работы с вашими документами и папками. Система сохраняет
историю диалогов, учитывает сведения о вас из доступной истории, работает
с документами и локальной папкой и помогает выполнять задачи.

Через чат доступны поиск по тексту с номерами строк, структура проекта,
создание документов по источникам, точная замена фрагментов и конвертация в TXT/MD/HTML/DOCX/PDF.
Можно попросить «создай документ о …» или «мне нужен PDF этого документа»:
агент подбирает операции, имя и источники. Явная просьба выполняется сразу,
предпросмотр включается по запросу. Исходная версия проверяется повторно,
для замены сохраняется резервная копия. Конвертация переносит текст без оформления
и изображений. Чтение репозиториев учитывает `.gitignore`, поддерживает исходники
и типовые файлы без расширения. Google Drive и общая библиотека сохранены.
Команды, форматы и ограничения: [docs/local-tools.md](docs/local-tools.md).
Короткие и длительные задачи получают разные ограниченные бюджеты. При заполнении
окна истории включается компактизация с сохранением полного архива и дословных
ограничений; прогресс и факт сжатия видны в чате.
[Как устроены память и бюджеты](docs/context-memory-and-task-budgets.md).
Источники ответа можно явно ограничить подпапкой или выбранными файлами;
просмотр папок не меняет область автоматически. Под ответом доступны сохранённые
фрагменты с позициями и проверкой актуальности исходника. Поиск объединяет
лексические и смысловые результаты. [Область источников и ограничения](docs/workspace-sources.md).
Выбор рабочей папки остаётся слева, без плашки над чатом. В Workspace доступны
проверка изменений, список новых/изменённых документов и повтор ошибок индексации;
неизменённые файлы не обрабатываются заново.
[Обслуживание индекса](docs/workspace-index-maintenance.md).
Кнопка «Индексировать папку» также сохраняет текст и позиции документов в SQLite:
повторные вопросы и перезапуск backend не требуют нового извлечения PDF/DOCX.
Готовый текстовый индекс ищет и за прежним пределом холодного обхода 500 файлов;
изменённые файлы не используют старую копию. При отказе индекса остаётся чтение
исходников. [Настройки, границы и проверки](docs/workspace-text-index.md).
Для задач с кодом доступен [репозиторный агент](docs/repository-agent.md):
«исправь ошибку в проекте и запусти тесты» включает чтение, правки и проверки
с обратной связью по их настоящему выводу. Изменения и журнал видны в чате.
Порядок дальнейшего развития: [план агентской платформы](docs/agent-platform-plan.md).
План развития и реальные замеры: [план](docs/local-assistant-improvement-plan.md),
[результаты 22 октября](docs/local-assistant-results-2026-10-22.md).
Отдельный сложный набор: [examples/complex_workspace](examples/complex_workspace/README.md).
Для ручной проверки выбирай вложенную папку `documents`; вопросы и критерии
хранятся отдельно. [Прогоны и ограничения](docs/complex-workspace-results-2026-10-22.md).

React + TypeScript + FastAPI, Assistant Core, локальные GGUF-модели через llama-server, Chroma и SQLite. Поддерживаются RAG, GraphRAG и внутренняя автоматическая редактура ответа. Пользователь получает готовый результат; ручное прохождение этапов убрано. Ollama не требуется для production runtime.

Подробности model provider, профилей, streaming, cancellation и настройки моделей: [docs/llama-runtime.md](docs/llama-runtime.md). Архитектура задач: [docs/assistant-core.md](docs/assistant-core.md).

Обычный ответ по workspace сохраняет содержательное описание персонажа после
проверки и не ограничивается одной ролью или четырьмя предложениями. Примеры,
самоописание и намерения передаются с их исходной атрибуцией; неверные факты
по-прежнему исключаются. См. [docs/answer-informativeness.md](docs/answer-informativeness.md).

Обычный обзор папки на локальной модели подготавливается одной цепочкой:
содержательные предложения, проверка по исходным фрагментам и ответ абзацами.
Для FAST/BALANCED/REASONING общий бюджет модельной обработки — 120/180/240 секунд.
Истечение времени не подтверждает непроверенные сведения. Настройки и границы:
[docs/response-latency.md](docs/response-latency.md).

Прямой вопрос к выбранной папке получает маршрут и обычную подробность без
дополнительных модельных вызовов. Если проверка остановилась по времени,
ответ сохраняет уже проверенные целые предложения и показывает причину остановки.
См. [docs/partial-answer-checks.md](docs/partial-answer-checks.md).

В FAST короткий обзор возвращает проверенные предложения без дополнительного
пересказа, а автоматическая редактура выполняет draft → edit. Смысловой аудит
может проверять два утверждения одним запросом с отдельными доказательствами;
`EVIDENCE_AUDIT_BATCH_SIZE=1` возвращает одиночные проверки. Граф автоматически
помогает обычному чату: конкретные вопросы по точным именам и идентификаторам
могут находить исходные фрагменты и цепочки без нового embedding-вызова.
При недостаточном покрытии выполняется обычный поиск; сосед добавляется только
для ещё не покрытой части вопроса. Карта в меню показывает близость документов: круглые узлы
документов, силовое размещение, подсветка соседей, перетаскивание и масштабирование.
Нажмите на линию: пояснение покажет числовую близость и похожие фрагменты двух
документов. Линия означает сходство содержания; тип отношения не назначается.
Отдельных вопросов и рабочего процесса в карте нет. Связи вычисляются из уже
сохранённых embeddings без новых модельных вызовов; папка и библиотека разделены.
Смысловая близость помогает поиску, а факты проверяются по исходному тексту.
Для новой папки откройте Workspace и нажмите «Индексировать папку»; обрабатываются
также вложенные папки. Смена workspace сама по себе обновляет только список файлов.
Подробности: [docs/graph-workbench.md](docs/graph-workbench.md) и
[docs/rag-performance.md](docs/rag-performance.md).

## Desktop-приложение (Tauri)

Desktop-оболочка использует тот же React UI и тот же FastAPI backend. При запуске она выбирает свободный loopback-порт, скрыто запускает standalone backend, ждёт `GET /api/health` и только затем показывает рабочий интерфейс. Backend помещается в Windows Job Object и завершается вместе с приложением. Второй запуск переводит фокус на существующее окно и не создаёт ещё один backend.

Для desktop-разработки нужны Rust toolchain, Visual Studio Build Tools с workload «Desktop development with C++» и Windows 10/11 SDK, а также существующее Python-окружение `.venv`. Основные команды из корня проекта:

```powershell
npm run frontend:dev     # React/Vite; backend отдельно на 8000
npm run backend:dev      # FastAPI с reload на 8000
npm run desktop:dev      # Tauri + Vite; backend стартует из корневой .venv
npm run desktop:build    # React dist + PyInstaller sidecar + Tauri installer
```

Backend dev из корня проекта:

```powershell
.venv\Scripts\python.exe -m uvicorn main:app --app-dir api --host 127.0.0.1 --port 8000 --reload
```

Production desktop хранит SQLite, Chroma, настройки, credentials и логи в системном AppData приложения `local.kontur.rag`. При первом переносе создаётся согласованный SQLite backup и временная копия остальных файлов; публикация и повтор после обрыва отслеживаются журналом миграции. Существующая пользовательская база не перезаписывается и не смешивается с чужим индексом. Исходники не удаляются. Секреты и рабочие базы не включаются в installer или React bundle. Обычный dev использует каталог `api`.

Название приложения — «Фортуна». Технические идентификаторы `local.kontur.rag`,
`KONTUR_DATA_DIR`, ключи локального хранилища и имя backend сохраняются для
совместимости: переименование использует существующие историю и настройки.
Название обновлено в интерфейсе, экспорте переписки, заголовке окна, настройках
установщика и общих инструкциях помощника. Постоянный профиль владельца между
чатами — отдельная возможность; переименование его не добавляет.

Если backend не готов за 180 секунд или завершился, окно показывает причину, хвост `backend.log` и кнопку повторного запуска. Первый запуск standalone backend может занять больше времени из-за распаковки и проверки Windows Defender. Микрофон использует прежние `getUserMedia`/`MediaRecorder`; WebView запросит системное разрешение при первом использовании.

## Запуск после установки

Запустите «Фортуна» из меню Start или через ярлык. Откроется обычное desktop-окно; backend и React UI запускаются автоматически без PowerShell, npm, uvicorn и браузера. Закрытие окна завершает скрытый backend. История, документы и индекс сохраняются в AppData между запусками.

Backend автоматически запускает llama-server скрыто и пишет вывод в `llama-server.log`. Embeddings используют отдельный сервер с `embedding-server.log`. Уже доступные серверы используются повторно. Загрузка модели не блокирует интерфейс; статус виден в заголовке чата. При закрытии завершаются только принадлежащие приложению процессы.

## Первый запуск на новом компьютере

Проверенное окружение: Windows, Python 3.12, Node.js 24 с npm, llama.cpp CUDA для NVIDIA GPU. Команды ниже выполняются в PowerShell из корня проекта.

### 1. Python-зависимости

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r api/requirements.txt
```

Активация виртуального окружения не требуется: команды явно используют Python из `.venv`.

### 2. Локальные модели

Разместите официальный Windows CUDA llama-server и DLL из соответствующего релиза в `runtime/llama`. Сохраните совместимую небольшую GGUF-модель чата (например Qwen 3.5 4B Q4_K_M) в `api/models/chat.gguf`, Nomic embedding GGUF — в `api/models/nomic-embed-text.gguf`. Пути переопределяются настройками из `api/.env.example`. Модели не входят в Git и installer. На новом компьютере положите их в каталог данных приложения по пути из сообщения о недостающей модели. Подробности и ссылки на модели — в [документации runtime](docs/llama-runtime.md).

### 3. Сборка desktop installer

```powershell
npm ci
npm run desktop:build
```

Сборка создаёт React assets, standalone `kontur-backend.exe`, Tauri executable и NSIS installer. Установите полученный `.exe` из `frontend/src-tauri/target/release/bundle/nsis/`, затем запускайте приложение из Start Menu.

### После изменений в интерфейсе

Пересоберите installer:

```powershell
npm run desktop:build
```

Если изменились зависимости или lock-файлы, перед сборкой выполните `npm ci` в корне и `npm ci --prefix frontend`.

## Хранение истории и работа с чатом

История хранится в таблице `workspace_chats` существующей SQLite-базы. При первом обращении импортируется `app/chat_history.json`, если он существует; исходный архив сохраняется. Импорт не повторяется после удаления диалога. Backend сохраняет ответ, контекст модели и завершение задачи одной SQLite-транзакцией. Повтор того же сообщения по request ID возвращает сохранённый ответ. Список загружается страницами по 50 диалогов, сообщения — при открытии. Названия ищутся на сервере, включая ещё не загруженные страницы; устаревшее сохранение с номером версии отклоняется.

При обновлении списка новая серверная версия чата обновляет его название и историю активного диалога, включая изменения из другой вкладки. При смене рабочей папки прежний активный файл и каталог сбрасываются. Вопрос по длинному выбранному файлу получает выдержки из нужных частей текста; ограниченный охват явно обозначается в ответе.

Кнопка `⋮` открывает меню поверх списка, Escape и клик снаружи закрывают его. Микрофон запрашивает системное разрешение WebView. Для записи используется MediaRecorder; для распознавания нужен настроенный Whisper.

Версии прямых Python-зависимостей зафиксированы по локальному окружению. Whisper для голосового ввода устанавливается отдельно:

```powershell
.venv\Scripts\python.exe -m pip install faster-whisper
```

Альтернатива — `openai-whisper`; для него нужен FFmpeg. Модели распознавания скачиваются при первом использовании.

## llama.cpp / model provider

See [runtime configuration, profiles and cancellation](docs/llama-runtime.md) and
[api/.env.example](api/.env.example). Chat inference and embeddings use separate
providers. The default deployment automatically starts llama-server for both;
there is no mandatory Ollama dependency, startup, warmup or Python SDK.

Profiles: `FAST`, `BALANCED` (default), `REASONING`. All initially share the
configured small GGUF; context defaults to 4096, GPU offload to `auto`, CPU
threads to 6. The embedded GGUF chat template handles system/user/assistant
messages. Structured routing, verification and graph extraction use JSON schema.

По умолчанию ответы по workspace и библиотеке проходят контекстную сверку:
объяснение сохраняется целиком, замечания отображаются отдельно, а изменения
затрагивают только повторно проверенные предложения. Технический отказ проверки
сохраняет ответ со статусом «не завершена», без автоматического сокращения до
цитаты. Убрано ограничение обычного библиотечного ответа в 1–3 предложения.
Положительные утверждения проходят независимый смысловой аудит цитат. При
переполнении контекста ответ проверяется частями с сохранением всех источников;
несколько точечных исправлений допустимы. Правила проверки не содержат словаря
конкретных документов или предметной области.
Строгая проверка доступна в редакторе этапов; `ANSWER_REVIEW_MODE=strict`
возвращает прежнюю цепочку. Подробнее: [контекстная сверка](docs/contextual-answer-review.md).

Task cancellation: `POST /assistant/tasks/{task_id}/cancel`. Provider cancellation
closes the actual HTTP stream, then Task/Action transition to CANCELLED.
`GET /api/model-status` reports readiness independently from backend health.
Metrics include TTFT, request/generation duration, tokens/sec and token usage.

SQLite and Chroma paths stay unchanged. Existing history is preserved. Changing
the embedding model requires reindexing; switching the same Nomic weights from
the old backend to llama.cpp preserves the embedding space.

## Режим разработки React

Для автоматического обновления интерфейса при редактировании нужны два терминала. Терминал 1 — API из корня проекта, **на порту 8000**, который задан в прокси Vite:

```powershell
.venv\Scripts\python.exe -m uvicorn main:app --app-dir api --host 127.0.0.1 --port 8000 --reload
```

Терминал 2 — Vite, также начните из корня проекта:

```powershell
cd frontend
npm run dev
```

При чистой web-разработке можно открыть адрес Vite, напечатанный в терминале. Это только developer convenience: production не открывает и не использует браузер. Для проверки desktop-окна используйте `npm run desktop:dev`.

## Интерфейс «Фортуна»

Основной экран — чат: история и поиск слева, переписка по центру и закреплённое поле сообщения внизу. У каждого диалога меню `⋮` для переименования и удаления. Кнопка в верхнем левом углу сворачивает и раскрывает панель. Выбор модели и скачивание переписки находятся сверху. «Документы» в левой панели открывает библиотеку поверх переписки.

Для вопросов по источникам редактура выполняется внутри приложения: FAST использует черновик и одну редактуру, BALANCED/REASONING также могут улучшить и собрать текст. Неизменённый результат завершает редакторскую цепочку без повторных одинаковых генераций. Этапы ограничены общим временем, итог проверяется по тем же источникам. Промежуточные версии доступны в деталях ответа, одобрять этапы не требуется. Профиль FAST/BALANCED/REASONING выбирается сверху. Кнопка «Стоп» отменяет обычный ответ и Live. Скрепка добавляет вложения; микрофон вставляет распознанный текст. Enter отправляет сообщение, Shift+Enter добавляет новую строку.

В окне документов доступны загрузка нескольких файлов, импорт Drive и удаление с подтверждением. Новый чат сохраняет библиотеку документов.

## Если не запускается

| Симптом | Что проверить |
| --- | --- |
| Desktop startup сообщает об ошибке | Откройте детали ошибки в стартовом экране и проверьте `backend.log` в AppData приложения; затем нажмите «Повторить». |
| Второй запуск не создаёт окно | Уже запущенный экземпляр должен получить фокус; проверьте панель задач Windows. |
| Ошибка подключения в Vite dev | Проверьте отдельный backend dev на порту 8000. Это не относится к установленному desktop приложению. |
| Модель не отвечает | Проверьте статус модели, пути GGUF и `llama-server.log` в каталоге данных. При недостатке VRAM уменьшите `LLAMA_GPU_LAYERS` или оставьте `auto`. |
| Микрофон недоступен | Разрешите приложению доступ к микрофону в Windows Privacy settings и установите Whisper для распознавания. |
| Google Drive недоступен | Выполните авторизацию из раздела ниже. |

## Форматы документов

Поддерживаются PDF, DOCX, HTML и UTF-8 TXT, включая короткие непустые тексты. Максимальный размер загрузки по умолчанию — 200 МиБ; сервер проверяет лимит и для аудио. HTML индексируется как текст без выполнения скриптов.

Для PDF без текстового слоя применяется OCR. Установите Tesseract с языками `rus` и `eng`, а также Poppler. Если они не доступны через PATH, задайте `TESSERACT_CMD` (путь к исполняемому файлу) и `POPPLER_PATH` (путь к каталогу bin). Смешанные PDF, где лишь часть страниц является сканами, требуют дополнительной доработки OCR.

## Google Drive

Создайте OAuth-клиент типа Desktop app с включённым Drive API и сохраните credentials в `api/credentials.json`. Авторизуйтесь отдельно:

```powershell
.venv\Scripts\python.exe api/gdrive_auth.py
```

Команда откроет браузер и создаст `api/token.json`. Сервер не запускает интерактивную авторизацию при импорте. Затем укажите ссылку на папку в интерфейсе. Импорт обходит подпапки, читает все страницы списка файлов и поддерживает экспорт Google Docs в текст. Файлы с одинаковыми именами различаются по Drive ID. Повторный импорт обновляет существующий документ по Drive ID; автоматической синхронизации изменений пока нет. Исходный текст и решение о замене индекса сохраняются одной SQLite-транзакцией. При ошибке записи сохраняется предыдущая версия, при успешном обновлении старые ответы исключаются из скрытого контекста модели.

## Ограничения

Приложение предназначено для личного локального использования. API проверяет Host, Origin и случайный токен запуска; desktop передаёт токен через IPC. Web/dev инициализирует доступ через защищённый endpoint. Это не многопользовательская система с ролями и разграничением документов. Программы, скрипты и ярлыки нельзя открывать через ассистента; типовые credentials исключены из чтения и индекса. Для документов действуют ограничения распаковки, текста, страниц и OCR; неполный PDF не выдаётся за полный. Подробности и границы: [исправления ревью](docs/review-fixes-2026-10-15.md).

При сбое индексации выполняется удаление частичного индекса. Если сам откат не удался, запись документа остаётся доступной для повторного удаления. SQLite и Chroma не поддерживают общую транзакцию, поэтому аварийное завершение процесса между операциями может потребовать сверки хранилищ.

## Структура проекта

Новые проверки пользовательских сценариев запускаются командой
`.venv\Scripts\python.exe -m unittest discover -s tests -v`.
Для проверки реальных ответов моделей:
`.venv\Scripts\python.exe tests/evaluate_user_queries.py --history`.
Методика, покрытие и выявленные проблемы: [проверка запросов](docs/user-query-evaluation.md).

В шапке чата можно выбрать установленную локальную Qwen 3.5 4B, 9B Q4,
9B Q3 или Gemma 4 E4B, отдельно от режима ответа. Модели остаются на диске; выбор сохраняется,
а сервер переключается на выбранные веса. Без сохранённого выбора используется
исходная конфигурация (в текущей установке — 4B).
Настройки и размещение моделей: [локальный runtime](docs/llama-runtime.md).
Замеры скорости и ограничения качества: [сравнение локальных моделей](docs/local-model-alternatives.md).

- `frontend/` — React-интерфейс и Tauri desktop shell.
- `api/` — FastAPI, поиск, работа с моделями и хранилища данных.
- `app/chat_history.json` — прежний архив истории, если существует; оставлен для одноразового импорта. Код старого интерфейса удалён.

Базы, `.env`, credentials и токены не относятся к временным файлам. Не удаляйте их при очистке проекта.
