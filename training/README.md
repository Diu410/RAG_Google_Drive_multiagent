# Qwen3.5-4B для «Фортуны»: первый эксперимент в Colab

Это комплект для **первого эксперимента с планировщиком**. Модель учится выдавать
JSON `AgentPlanDecision` по текущему каталогу навыков. Сами операции не выполняются.
Набор небольшой и синтетический: он проверяет обучение и экспорт, но не доказывает
улучшения модели на реальных задачах. Генерация ответов по документам, запись файлов,
мышь, клавиатура и управление окнами здесь не обучаются.

## Что делать по порядку

1. Из корня проекта подготовьте архив:

   ```powershell
   .venv\Scripts\python.exe scripts/prepare_fortuna_colab.py
   ```

   Появится `.training-output/fortuna-colab.zip`. В нём только синтетические
   задания, код проверки, системная инструкция и публичные схемы приложения.
   Скрипт не читает историю чатов, базы, документы пользователя или credentials,
   не запускает модели и не выполняет файловые команды из примеров.

2. Откройте https://colab.research.google.com/ → **Файл → Загрузить блокнот** →
   выберите `training/Fortuna_Qwen35_4B_LoRA.ipynb` из проекта.
3. Выберите **Среда выполнения → Сменить среду выполнения → GPU**.
   Фактически выделенную карту и свободную VRAM проверит notebook. Unsloth
   указывает ориентир 10 ГБ для BF16 LoRA 4B; это не гарантия для любой длины
   контекста. BF16 используется только на поддерживающей его карте, иначе FP16.
   При OOM уменьшайте контекст только после проверки длины всех примеров или
   выбирайте более вместительную карту. QLoRA здесь выключено.
4. Выполните ячейку установки. Если Colab просит перезапуск, перезапустите
   **сеанс**, затем продолжите с ячейки импорта; переустанавливать всё повторно
   в этом же сеансе не требуется.
5. В ячейке загрузки выберите **только** `fortuna-colab.zip`.
6. Оставьте `SMOKE_TEST = True`: первый запуск — пять шагов обучения и короткая
   проверка на validation. Проверьте, что зависимости, шаблон, loss и сохранение
   адаптера работают. Это не оценка качества.
7. Затем начните новый сеанс и поставьте `SMOKE_TEST = False`. Notebook обучит
   одну эпоху, сравнит исходную модель и адаптер на validation, после завершения
   выполнит отдельный test. Веса test не участвуют в обучении и выборе checkpoint.
8. Скачайте архив адаптера и отчётов последней ячейкой. Сохраните его до закрытия
   сеанса: диск Colab временный. Экспорт GGUF включается отдельно в конфигурации;
   он требует дополнительного времени, RAM и места на диске. Он создаёт новые
   файлы и не заменяет установленную модель «Фортуны».

## Что измеряется

- `json_valid`: ответ разбирается как JSON без удаления обёрток/ошибок.
- `contract_valid`: схема, известные операции, зависимости и ссылки на outputs.
- `decision_match`: нужен ли многошаговый план.
- `plan_match`: совпадают операции, аргументы, зависимости и запрос подтверждения.
  Имена шагов, reason, confidence и пересказ objective не влияют на совпадение.
  Это консервативная проверка: равнозначный пересказ `arguments.question` может
  не совпасть со справочником. Просматривайте также сохранённые ответы.

**Это не процент выполненных задач на ПК.** Здесь нет запуска исполнительного
цикла, работы с диском или проверки последствий действий. Генерация в Colab
выполняется без JSON-грамматики llama.cpp: проверка формата строже, а поведение
runtime после экспорта нужно измерить отдельно. Общие messages и каталог взяты
из runtime, но токенизация/JSON sampler между Transformers и llama.cpp различаются.
Для настоящего замера нужны изолированные тестовые папки и весь исполнитель.

В коротком режиме используются первые два validation-примера; test пропускается.
В полном режиме обе модели получают одинаковые запросы и настройки. Базовая
модель оценивается с отключённым адаптером, в памяти остаётся одна модель.
Отчёты содержат ответы, результаты по категориям, время и число токенов.
Время на нескольких коротких примерах не является устойчивым benchmark скорости.

## Как расширять данные

Исходные задания находятся в `training/seed_cases.py`. Добавляйте разнообразные
запросы и проверенные планы, затем пересобирайте архив. Связанные перефразировки
объединяйте одним `group` в одном split. Не размножайте один шаблон тысячами имён.
Новые сценарии проверяются по актуальной схеме приложения. При изменении
системной инструкции или контракта инструментов пересобирайте весь комплект.

Для содержательного эксперимента сначала расширьте train несколькими сотнями
разнообразных проверенных заданий и добавьте независимые проверки по категориям.
Оставьте финальный test для одного сравнения после выбора настроек на validation.
Текущий комплект принимает только синтетические задания. Для реальных журналов
понадобятся отдельные экспорт, обезличивание и проверка разрешения на передачу.

Поиск, чтение, сравнение и открытие в примерах не требуют подтверждения. Нынешний
исполнитель не поддерживает удаление/переименование/запись, поэтому модель учится
не выдумывать такие операции; `should_plan=false` лишь возвращает управление
обычному обработчику, а не означает самостоятельный отказ или успешное выполнение.
Расширение возможностей потребует реализации инструментов и новой версии данных.

Не подключайте узко обученную модель сразу ко всем вызовам приложения: сейчас
один chat-server обслуживает также ответы, редактуру и проверку источников.
Проверьте эти сценарии после экспорта либо отдельно реализуйте выбор адаптера
для планировщика. В комплекте нет автоматического переключения рабочей модели.

Документация проверена 15 октября 2026 года:

- [Официальный notebook Unsloth Qwen3.5-4B, использованный как справочник API](https://github.com/unslothai/notebooks/blob/59d5a1b8216e5f67c5e3ccf37a5ecae94a950a14/nb/Qwen3_5_%284B%29_Vision.ipynb).

- [Ограничения ресурсов Colab](https://research.google.com/colaboratory/faq.html).

Комплект использует текстовую часть модели, LoRA rank 16, отключённое размышление
для короткого JSON и loss только на ответе. Версия исходных весов закреплена;
pip freeze сохраняется в отчёт. Notebook устанавливает зависимости в Colab,
а не в venv приложения. Версии ключевых библиотек закреплены на проверенных
документацией API; совместимость CUDA, kernels и фактический расход VRAM требуют
запуска на выделенной GPU. Локальная проверка структуры и CPU-тесты не являются
подтверждением успешного обучения или GGUF-конвертации в Colab.
