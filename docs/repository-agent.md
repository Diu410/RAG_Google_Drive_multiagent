# Агент работы с репозиторием

Фортуна выполняет задачи с кодом через обычный чат выбранного workspace:

```text
В проекте падают тесты, разбери и почини
Можешь исправить ошибку в calc.py и запустить тесты?
Исправь код проекта, но тесты не меняй
Проанализируй код проекта, только план без изменений
Исправь ошибку в коде проекта, но не запускай тесты
```

`repository_agent` зарегистрирован в Assistant Core. Прямой запрос работы с
репозиторием поступает в него до составления общего плана, переписывания истории
и инструментов документов. Прежние чтение документов, RAG и Google Drive сохраняются.
Никаких отдельных форм для вызова инструментов не требуется.

## Выполнение

Агент видит доступные пути, ID проверок, ограниченный контекст корневого AGENTS.md
и каталог навыков. Навык `repository-maintenance` загружается инструментом по
необходимости. Это процедурная инструкция приложения, не запуск скрипта.
Следующее действие выбирается после результата предыдущего; ошибки инструментов
возвращаются модели. Полный журнал сохраняется в существующих задачах/действиях SQLite.

Действия имеют отдельные JSON-схемы аргументов: `read`, `search`, `edit`, `rewrite`,
`write`, `check`, `skill`, `finish`. Не относящиеся к инструменту параметры не
передаются модели как общие поля. `edit` требует дословный старый фрагмент и одно
совпадение. `rewrite` получает массив строк небольшого файла; нужны полное чтение,
до 80 строк/4000 символов и неизменившаяся версия. `write` создаёт новый файл и
не перезаписывает существующий. Родительская папка должна существовать.

Политика пути, корня, секретов, скрытых/служебных папок и symlink/junction сохраняется.
Исходники редактирует отдельный экземпляр `SourceChanges`: это не расширяет
прежний API документов до записи исполняемых файлов. Текстовые кодировки и
окончания строк сохраняются; для замены создаётся `.fortuna-backups/`.
Полная замена Python проходит разбор AST и сохраняет имена существующих
функций/классов/методов: обрывок с одними импортами не заменяет весь модуль.
Удаление, переименование, установка зависимостей и Git-запись не добавлены.

Права определяются исходной просьбой. Анализ и «только план» не разрешают запись
или запуск. Запрет менять тесты ограничивает тестовые пути и не превращает
ремонт исходников в глобальный запрет записи. «Не запускай» исключает проверки.
Содержимое файлов, навыков и результаты процессов не расширяют права.

## Проверки проекта

Обнаруживаются Python-тесты в `tests/` и существующие npm scripts с именами
`test`, `build`, `lint`, `typecheck` в корневом `package.json`. Для Python выбирается
локальная `.venv`, если доступна, иначе Python текущего окружения; в упакованном
backend используется установленный Python из PATH. Для npm нужны Node.js и npm.
Функции pytest отделяются от unittest; зависимости автоматически не устанавливаются.

`check` принимает только ID каталога. Аргументы процесса формирует приложение,
`shell=False`, stdin закрыт, окно Windows скрыто. Лимит одного процесса — 45 секунд,
вывод ограничен хвостом 16 000 байт. Отмена и общий дедлайн останавливают собственный
процесс; на Windows активное дерево завершается через taskkill по конкретному PID.
Приложение не останавливает другие серверы или процессы по имени.
После правки приложение автоматически запускает подходящую обнаруженную
проверку и возвращает результат модели; отдельное решение модели для этого
не требуется. Каталог обновляется после изменения конфигурации. Повреждённый
package.json становится диагностикой, не обрывает задачу до чтения исходников.

Код проекта выполняется с правами пользователя. Это ограниченный интерфейс запуска,
не песочница ОС: тесты и npm scripts способны выполнять собственный код и создавать
дочерние процессы. Переменные с TOKEN/SECRET/PASSWORD/API_KEY не наследуются;
для хранилищ Фортуны и Python-кеша выделяются временные пути. Изоляция кеша
исключает устаревший bytecode при повторной быстрой правке той же длины.

Репозиторная работа относится к LONG: общий предел `LONG_TASK_SECONDS` (по умолчанию 540 секунд); максимум 10 решений
за задачу. Повтор одинакового действия без изменения состояния останавливается.
Контекст измеряется tokenizer: прежние наблюдения сокращаются с явными метками,
объективная задача, права и журнал эффектов сохраняются. Полные действия остаются в SQLite.

«Задача выполнена» требует настоящий успешный запуск после последних изменений,
если запуск разрешён запросом. Нулевой набор тестов не считается успехом.
При отсутствии проверок, их падении, обрыве модели или лимите шагов возвращается
`INCOMPLETE` с сохранёнными изменениями. Неподтверждённое обещание finish не заменяет
результат процесса. Успех выбранных тестов не доказывает полной корректности проекта.
При отмене уже опубликованная атомарная запись остаётся завершённым эффектом
в журнале; последующие действия не запускаются. Отмена не откатывает файл молча.

## Интерфейс и воспроизведение

Ответ содержит пути изменений и фактические проверки. «Действия, изменения и проверки»
показывает чтение, правки, diff, код выхода и вывод из журнала задачи, включая после
перезагрузки страницы. История не содержит скрытых рассуждений модели.

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -p test_repository_agent.py -v
.venv\Scripts\python.exe tests/benchmark_repository_agent.py
# Если сервер 8081 уже работает, чтобы не загружать вторую модель:
.venv\Scripts\python.exe tests/benchmark_repository_agent.py --reuse-running
npm --prefix frontend run build -- --configLoader runner
node tests/local_tools.browser.cjs
```

Реальный benchmark копирует `examples/agent_workspace` в `.user-evaluation/`,
использует отдельные SQLite/Chroma, проверяет независимое поведение кода и хеши
тестов/конфигурации, исходных примеров, рабочей базы и выбора модели.
Успешный контролируемый браузерный тест не считается доказательством качества GGUF.
