# Сложный workspace: качество и скорость, 22 октября 2026

Набор создан по запросу пользователя внутри текущего проекта:
[examples/complex_workspace](../examples/complex_workspace/README.md).
Для ручной работы выбирается вложенная папка `documents`, а не прежний Obsidian.
Obsidian использовался ранее потому, что он был сохранён как активный workspace
в рабочей SQLite. Для новых прогонов личные файлы не нужны; сохранённый выбор
приложения и существующая история не менялись.

## Набор и протокол

15 вымышленных источников, 11 вопросов полной цепочки и 8 пар верного/искажённого
черновика. Проверяются смена редакции и два согласования, однофамильцы с разными
ID, условие с аварийным исключением, сумма CSV с фильтром по статусу, конфликт
журналов без приоритета, оговорка в конце отчёта длиной более 20 тысяч символов,
область отрицания, внедрённая команда, отсутствующий телефон, цепочка связей
через контракт, UTC-смещения и значение `override=0` в исходнике Python.
Код примера не исполняется.

Вопросы и независимые ожидаемые факты находятся вне папки источников. Модель
не получает эталоны. Каждый реальный прогон копирует источники, использует свои
SQLite/Chroma и серверы на свободных портах. Проверяются хеши исходных примеров,
рабочей базы и сохранённого выбора модели. Запускается Qwen 3.5 4B, BALANCED,
`use_multi_agent=true`, штатная контекстная сверка и компактный независимый аудит.
Запуск модели, прогрев и индексация исключены из задержки ответа.

Оценка ответа требует всех запрошенных фактов, нужных источников, завершения
задачи и сверки именно показанного текста. Для запроса отсутствующего телефона
допустим штатный смешанный статус: все положительные утверждения `SUPPORTED`,
только телефон `UNANSWERED` / `INSUFFICIENT_INFORMATION`. Неподтверждённые факты,
посторонние сообщения об отсутствии сведений и технический отказ не проходят.
Для верного контрольного черновика нужны неизменность и `SUPPORTED`; для
искажённого — завершённая проверка без подтверждения исходной ложной фразы.

## Исправления

Один информационный вопрос больше не запускает длинный план только из-за слов
«выполненное», «открытие», просьбы сохранить условия или показать расчёт.
Явные команды с файлами остаются действиями. Просьба краткого ответа не означает
обзор всех документов. Краткие ответы проходят первую редактуру и итоговую
сверку, без дополнительных enhance/merge. Инструкции сохраняют все части вопроса
и промежуточные идентификаторы, а не только конечный результат.

Нативные цитаты объединяют соседние дословные предложения и заголовки. Аудитор
получает исходные переносы CSV, а не одну строку. Это сохраняет операнды, фильтры,
модальность, привязку имён и область условия. Регулярные падежные формы имени
распознаются вместе с точным ID; анонимный голос не получает имя из соседнего
текста. Независимый смысловой аудит и защиты направления/модальности сохранены.

Числовые подсказки считают ограниченные суммы по явно подписанным группам CSV
и нормализуют явные UTC-смещения. Они не являются цитатами и не доказывают выбор
строк или общность дат. Явно ложное равенство отклоняется точной арифметикой,
даже если модель оценила его положительно. AST допускает только ограниченные
числовые операции; код из текста не исполняется.

Для двух временных меток есть отдельный точный расчёт: один источник, явная
общая корректная дата, два UTC-смещения, привязка к названному ID или файлу.
Программа цитирует исходные строки, считает UTC, сдвиг суток и разницу.
При неоднозначности используется обычный RAG. В журнале сохраняется доказательство
`CALCULATE_SOURCE_TIMES`; UI называет результат «Вычисление по источнику»,
а не модельной оценкой. Это вычислительный инструмент без новой генерации текста.

Список «Использованные файлы: …» распознаётся как оформление только для реально
выбранных путей. Фактическое предложение после метки источников продолжает
проверяться. Исправление устраняет лишние аудиты служебных строк и ложные отказы.

## Исходные и промежуточные результаты

Исходный прогон: `.user-evaluation/20261022-125521/`. После применения одинаковых
уточнённых критериев к сохранённым ответам — **18/27**: 5/11 полных ответов и
13/16 проверок черновиков. Оригинальный отчёт 16/27 сохранён: два верных ответа
не совпали с чрезмерно буквальными шаблонами («недействителен», «не None»).
Уточнения формата применяются к обеим сериям; исходные ответы не переписываются.

Проба увеличения reasoning аудита до 128 токенов (`20261022-131752`) дала 7/9:
помогла сумме и отрицанию, но не устранила путаницу UTC и ухудшила оценку верного
сообщения о конфликте. Поэтому увеличение reasoning не включено для всех
запросов. Дополнительные исходные пробы сохранены: `131116`, `132449`.
В `133204` выполнены полные повторы до исправления служебных списков файлов;
эти данные также сохраняются, а отказы не исключаются из отчёта.

## Итог двух повторов

Последний прогон: `.user-evaluation/20261022-134546/`. По единым критериям
**51/54** против исходных **18/27**. Полные ответы: **19/22** против **5/11**.
Контрольная сверка: **32/32** против **13/16** — сохранены все 16 верных
черновиков, ни одна из 16 исходных ложных фраз не получила подтверждение.
Хеши рабочей базы, выбора модели и всех 15 исходников остались прежними.

Оригинальный итог 49/54 сохранён. Два корректных ответа не совпали с форматом
шаблона: `12 (партия L-11) + 5 (партия L-13)` и слово «расхождение» вместо
«расходятся». Содержание и завершённая сверка в обоих случаях верны. Проверка
уточнена, затем **обе** серии оценены одним кодом без повторной генерации;
`complex-comparison.json` хранит исходные и пересчитанные результаты и хеши
критериев. Ни один неподтверждённый ответ этим пересчётом не принят.

Полный набор из 11 вопросов занимал **387,24 с** в исходном прогоне, **189,89 с**
и **249,95 с** в заключительных повторах. В среднем на этот набор ушло на 43,2%
меньше времени; число модельных вызовов уменьшилось с **95** до **55/53**.
Это времена всех попыток, включая отказы. Один исходный и два заключительных
повтора не доказывают устойчивое ускорение произвольных вопросов.

Ускорение неравномерно: журналы и длинный отчёт стали медленнее, цепочка через
контракт теперь включает запрошенный промежуточный ID. Особенно большое
сокращение времени на однофамильцах связано с устранением ошибочного длинного
плана; сравнение UTC выполняет отдельный точный инструмент.

Три оставшихся отказа сохранены. В одном ответе об отрицании модель добавила
ненужные определения и список: основная мысль верна, дополнительный текст
полностью не подтверждён. В двух ответах по Python правильно получено 0, но
аудитор не подтвердил подстановку `override=0` в `return override`. Это ложные
отказы сверки; доработка транспорта не устраняет ограничение рассуждений 4B.
Существующий статус остаётся видимым пользователю. Набор не даёт основания
обещать безошибочный анализ произвольного репозитория.

## Автоматические проверки

Полный offline-набор — **584/584**. После уточнения ограничений калькулятора
отдельно повторены все **18/18** тестов сложного workspace, включая неверную дату,
отрицание общей даты, относительную дату, чужой ID, два подходящих источника,
сдвиг суток и проход через обычный чат без вызова модели. Журнал полного набора:
`.user-evaluation/complex-offline-tests-final.log`.

TypeScript и production-сборка прошли. `tests/local_tools.browser.cjs` прошёл
в headless Edge на настоящих изолированных API, SQLite и файлах: поиск,
предпросмотр, сохранение с резервной копией и конвертация в PDF. Также проверены
ссылки новой документации и `git diff --check`.

## Воспроизведение

```powershell
.venv\Scripts\python.exe tests/benchmark_complex_workspace.py --phase both --repeats 2
.venv\Scripts\python.exe tests/report_complex_workspace.py --baseline .user-evaluation/20261022-125521 --candidate .user-evaluation/20261022-134546
.venv\Scripts\python.exe -m unittest discover -s tests -v
npm --prefix frontend run build
```

В ограниченном Windows-окружении сборка использовала
`npm --prefix frontend run build -- --configLoader runner`.
Полные ответы, проверки, метрики, времена действий и хеши остаются в игнорируемой
`.user-evaluation/`. Набор синтетический, повторов мало; результаты не дают
надёжного p95, гарантии точности произвольных документов или замеров других GGUF.
Installer в этой задаче не пересобирался.
