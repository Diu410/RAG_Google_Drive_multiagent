# Доработка поиска по графу

Добавлен `api/graph_retrieval.py`: кеш точных упоминаний имён и идентификаторов,
поиск путей до двух переходов и выбор исходных фрагментов под конкретный вопрос.
При полном лексическом покрытии вопроса embedding/MMR пропускается. Промежуточные
источники и альтернативные сведения сохраняются. Обзоры, отрицание, формулы,
недостаточное покрытие и устаревшие источники используют обычный поиск.

Дополнение к обычному поиску требует нового совпадения по вопросу. В workspace
выбирается релевантный якорь; сосед использует остаток бюджета, сохраняя прямые
выдержки. Генерация и проверка ответа остаются включёнными.

Проверки: 460/460 unittest. На прежних 28 вопросах сохранён полный набор
обязательных источников. Контрольный замер поиска, генерации и контекстной
проверки на четырёх коротких вопросах, по два повтора: медиана 5,19 с без графа
и 3,55 с с графом; проверки ответов 6/8 и 8/8 соответственно. Это небольшой
синтетический набор, а не гарантия ускорения всех запросов. Начальное построение,
загрузка моделей и прогрев исключены. Базы измерений изолированы.

Данные замера: `.user-evaluation/graph-retrieval-20261013-001544/result.json`.
Прогон с исходными 28 вопросами:
`.user-evaluation/graph-retrieval-20261013-001128/result.json`.
Последний повтор (`graph-retrieval-20261013-002208`) сохранил те же выбранные
источники и 8/8 успешных ответов графа. Он обнаружил изменение рабочей SQLite
во время прогона; для контрольных цифр выше используется предыдущий прогон
с успешной проверкой неизменности рабочей базы. Базы самого benchmark изолированы.

Для ручной проверки перезапустите backend и используйте проиндексированную
папку или библиотеку. `GRAPH_RETRIEVAL_ENABLED=false` в `api/.env` отключает
новый поиск и его расширение для сравнения; после смены значения также нужен
перезапуск. Карта продолжает показывать смысловую близость документов.

```powershell
.venv\Scripts\python.exe tests/benchmark_graph_retrieval.py --answers --repeats 2
```
