# Обзор по предварительно проверенным сведениям

Этот путь сохранён для `ANSWER_REVIEW_MODE=strict`. Обычный чат по умолчанию
использует [контекстную сверку связного черновика](contextual-answer-review.md).

Короткие обзорные вопросы выбранного workspace теперь проходят цепочку
«содержательные предложения → независимая проверка → ответ».
Дополнительный пересказ и его проверка используются в REASONING; у провайдеров
без выбора доказательств по ID сохраняется прежний пересказ BALANCED.
Точка входа — `OverviewSynthesizer.compose`, реализация — `api/overview_facts.py`.
Развёрнутые ответы и общая библиотека документов сохраняют существующий путь.

Локальный провайдер выбирает точные исходные предложения по `evidence_id`,
не переписывая длинные цитаты. Он подготавливает до восьми предложений на источник
и восьми на обзор. Провайдеры без этой возможности извлекают до трёх предложений
на источник, до шести на обзор, с дословной цитатой.
Дословная непрерывная цитата должна присутствовать как в переданном фрагменте,
так и в исходном фактическом тексте. Каждое предложение независимо проверяется
`EvidenceAuditor`: субъект, действие с объектом, модальность и относимость
к исходному вопросу. Поля извлекателя не служат доказательством. Для узких
сообщений о структуре текста используются существующие дословные правила
проверки требований и примеров с сохранённым контекстом.

Смысловая проверка — отдельный вызов текущей модели, а не другая модель.
Проверенное сведение содержит предложение, субъект, действие, модальность,
область утверждения, источник и цитату. Сведения разных источников сохраняются
раздельно, включая противоречащие даты. Представление «В документе …» добавляет
атрибуцию источнику без изменения проверенного утверждения. Оно не устанавливает
реальность описанной организации или персонажа.
Проверка относится к целому предложению: извлечённые моделью поля субъекта
и действия служат метаданными и не заменяют его доказательство. Недостающая
конечная пунктуация добавляется до проверки, чтобы предложения не сливались.

Писатель получает только проверенные предложения и их атрибуцию и модальность.
Исходная цитата и соседний текст остаются в доказательствах и журнале; они не
передаются писателю. Каждое предложение ответа ссылается на одно сведение.
Неизменённое предложение сохраняет проверку. Новый пересказ независимо
сопоставляется только с указанным проверенным сведением, поэтому соседний факт
источника не может служить обоснованием дополнения. Проверка сохраняет
документальную область утверждения; ответ без привязки к тексту не заменяет
сообщение о документе. Неверное имя источника и потерянная местоименная ссылка
отклоняются. Новый пересказ не наследует старый вердикт.
После успешной проверки содержания явные рамки «В документе «имя» указано,
что …» и «…, согласно документу «имя»» сохраняют документальную область
даже при ошибочной модельной метке `FACT`. Имя должно совпадать с источником
единственного указанного сведения. Правило не подтверждает содержание,
не исправляет отрицательный аудит и не восстанавливает относимость;
в журнале отмечается `scope_adjustment=explicit_document_frame`.

Предусмотрена одна попытка написания. После ошибки, обрыва или отклонения
пересказа сохраняются исходные проверенные предложения. Неиспользованные
сведения также сохраняются. При отсутствии содержательных проверенных сведений
доступны дословные тематические цитаты с ограниченной областью ответа; они
не заполняют порог `EXPLANATORY`. Невозможность подготовить даже такую опору
отмечается техническим отказом, без свободной генерации и повторной цепочки
восстановления. Отмена генерации распространяется наружу.

Журнал `GENERATE_RESPONSE.data.fact_preparation` хранит допущенные сведения,
причины отказов, ошибки, пропуски фрагментов, время подготовки и число попыток
написания. Смысловые оценки отмечены фазами `FACT_PREPARATION` и `RETELLING`.
Панель проверки оценивает показанный `checked_answer`. Повторная проверка
не запускается, если подготовленный проверенный ответ остался неизменным.

Это ограниченный короткий обзор: максимум восемь сведений при выборе доказательств
по ID (шесть в прежнем контракте цитат), максимум три фрагмента
из одного источника, предупреждение при технических пропусках. Успешная проверка
не гарантирует полноту документов или безошибочность модельной смысловой оценки.
Для упрощённых пользовательских провайдеров без структурированной генерации
сохраняется прежний путь `OverviewSynthesizer`.

## Проверки

`tests/test_overview_facts.py` проверяет независимость подготовки и написания,
выдуманные цитаты, усиление намерения до события, добавление истинного, но
неподготовленного факта, ошибочную атрибуцию, независимый пересказ, сохранение
неиспользованных сведений, противоречия источников, обрыв, отмену и интеграцию
с журналом workspace. Личные источники и результаты реальных прогонов остаются
в игнорируемой `.user-evaluation/`.

Полный offline-набор после подключения цепочки: **313/313**, успешно;
из них 20 сценариев непосредственно проверяют подготовку сведений.
Проверены пути ссылок в обновлённой документации. Frontend и desktop не
изменялись и отдельно не собирались в этой задаче.

## Реальные прогоны 4B и воспроизведение оценки

На установленной Qwen 3.5 4B выполнены исходный вопрос с замороженными источниками
из истории и три нейтральных сценария. Сценарий разных дат повторён после
исправления конечной пунктуации. Использовались отдельные собственные серверы,
контекст клиента 4096, серверный контекст 8192, 8 GPU-слоёв и 6 потоков.

| Сценарий | Результат |
| --- | --- |
| Исходный обзор | `SUPPORTED / EXPLANATORY`, два текстовых сведения; панель совпадает с ответом |
| Карты и дата основания архива | Подтверждены оба сведения, достигнут порог объяснения |
| Карты и намерение руководителя открыть выставку | Сохранено одно сведение; намерение ошибочно признано моделью посторонним, порог объяснения не достигнут |
| Разные даты в двух документах | Сохранены обе даты с отдельной атрибуцией и факт о картах; достигнут порог объяснения |

Последнее правило документальной рамки проверено воспроизведением всех девяти
реальных структурированных ответов последнего прогона 4B. Для каждого вызова
проверены полное равенство prompt и схемы с записанным вызовом. После изменения
только обработки оценки приняты проверенные формулировки пересказа с обеими
датами и правильными именами документов. Это воспроизведение записанных
модельных оценок, а не новый запуск генерации. Сами модельные вердикты не
изменены; сохранены исходные поля и причина корректировки области утверждения.

Остаются ошибочные отказы по относимости и классификации модальности локальной
модели. Поэтому нельзя заявлять безошибочность обзоров или выигрыш скорости.
Контрольные суммы рабочей SQLite-базы и файла выбора модели совпали до и после
обоих запусков; собственные серверы остановлены. 9B, живой retrieval, HTTP,
frontend и desktop в этой задаче отдельно не проверялись.
