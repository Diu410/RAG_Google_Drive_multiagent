# Локальная папка: область источников и проверяемые фрагменты

Это первый этап перехода к помощнику по локальным материалам. Google Drive и
репозиторный агент сохранены; новые возможности относятся к работе с папкой.

## Пользовательский путь

Рабочая папка выбирается слева; отдельной плашки над чатом нет.
В открываемом оттуда Workspace можно явно выбрать всю рабочую
папку с вложенными папками, подпапку или от одного до 100 документов.
Переход по списку и предпросмотр файла не меняют область. Последний файл нельзя
убрать неявно с расширением до всей папки: для этого есть отдельная кнопка.
Область фиксируется в пользовательском сообщении перед отправкой и восстанавливается
из истории. Повтор использует исходные параметры, а не текущую навигацию.

Область применяется к поиску workspace и созданию нового текста по источникам,
включая пересказ папки. Она не разрешает запись и не заменяет проверку намерения.
Прямые команды чтения/открытия именованного файла остаются явными файловыми
действиями. Назначение записи определяется отдельно прежними правилами
`workspace_directory`/активной папки и запросом. Явный запрос общей библиотеки
сохраняет прежний отдельный маршрут.

Под ответом есть один раскрываемый блок источников: новые записи показывают
структурированные фрагменты, старые без них — сохранённый текст контекста.
Эти представления не выводятся одновременно. Список поддерживает и библиотеку;
одинаковые ID фрагментов не повторяются. Это снимки выбранного
контекста, не заявление, что каждый фрагмент подтвердил каждый факт. Сверка
остаётся отдельной. Для текста показаны строки, для PDF — доступные страницы,
для DOCX — доступные метки раздела/стиля блока без выдуманных номеров страниц.
Проверка актуальности читает диапазон только при совпадении ревизии. Изменение
файла даёт 409; старый фрагмент в истории не заменяется новым. Это проверка версии,
не истинности содержания. Визуального просмотра оригинального PDF/оформления DOCX нет.

## API

Необязательное `source_scope` в `/assistant/input`, `/assistant/stream`,
`/assistant/live` и `/query`:

```json
{"kind":"workspace"}
```

```json
{"kind":"directory","directory":"Материалы/Проект"}
```

```json
{"kind":"files","files":["Материалы/Условия.docx","Расчёты.csv"]}
```

Требуется `workspace_id`; нельзя совмещать с `graph_selection`. Несогласованные
и неизвестные поля отвергаются. Пути относительные с `/`; `..`, абсолютные пути,
NTFS streams, симлинки/junction и credentials не получают новых разрешений.
Недоступные/исключённые выбранные файлы не подменяются похожими и не выдаются
за отсутствие фактов в прочитанных документах.

Область возвращается в ответе, сохраняется с сообщениями и в метаданных задачи.
Другой набор источников или папка назначения с тем же `request_id` даёт конфликт,
не повторное действие. Смена области сбрасывает ожидающее подтверждение старой
операции. Шаг LLM-плана не может переопределить область исходного запроса.
Без нового поля старые клиенты сохраняют прежний маршрут и параметры навигации.

`results[].metadata` дополнены `revision`, полуоткрытым диапазоном символов
извлечённого текста `source_range` и списком исходных блоков `locations`
с доступными страницами/строками/метками разделов.

`GET /workspaces/{workspace_id}/source?path=...&revision=...&start=...&end=...`
проверяет файловые ограничения/ревизию и возвращает текст/позиции. Лимит фрагмента
32000 символов; требуется обычный токен локального API.

## Реализация

`WorkspaceDocumentReader.read_document()` возвращает неизменяемые текст, ревизию
и блоки. Совместимый `read()` возвращает тот же текст. Метаданные загрузчиков
PDF/DOCX больше не теряются при объединении текста workspace. ID блоков стабильны
в пределах ревизии; одинаковый текст разных позиций не объединяется. Это не
постоянная идентичность абзаца между редакциями.

Лексические и смысловые кандидаты обычного поиска собираются независимо.
Файлы ранжируются reciprocal rank fusion без сравнения лексических счётчиков
с embedding distances. Повторные совпадения одного канала не дают повторных
голосов. Смысловой кандидат сохраняет буквальный якорь, чтобы перефразированный
вопрос не получал только начало длинного файла. Затем выбираются буквальные
диапазоны с прежним ограничением контекста.

Область векторного поиска фильтруется до top-k. Устаревшие векторы не допускаются
в контекст. Ревизия и буквальное совпадение диапазонов проверяются при назначении
позиций. Точные имена сохраняют приоритет; имя вне выбранной области не расширяет
фактический контекст. Без embeddings остаётся лексический путь.
Прежний графовый быстрый маршрут сохранён только для неограниченной области
с прежними проверками. Ограниченная область не получает соседей извне.
Пересказ всей области использует инвентаризацию, не top-k. Явно названная подпапка
может дополнительно сузить выбранную область.

## Проверки и границы этапа

`tests/test_workspace_sources.py` проверяет область, фильтрацию, ранжирование,
смыслового кандидата при нескольких лексических совпадениях, конфликты ревизий,
позиции PDF/DOCX/текста, сохранение истории и fingerprint.
`tests/workspace_sources.browser.cjs` использует production UI и отдельные
настоящие API/SQLite/файлы: выбор области, навигацию, несколько файлов, снимок
цитаты, изменение исходника, reload и токен. Автор в browser-прогоне контролируемый;
это не оценка качества GGUF.

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -p test_workspace_sources.py -v
npm --prefix frontend run build
node tests/workspace_sources.browser.cjs
```

Для browser-набора требуется Node-модуль Playwright и Edge; переменная
`PLAYWRIGHT_MODULE_PATH` может указывать на модуль вне проекта.

Проверка реализации: полный offline-набор — 734 теста успешно; профильный набор —
27 тестов успешно, включая настоящий двухстраничный PDF. TypeScript/production
build, `git diff --check` и оба browser-сценария `workspace_sources.browser.cjs` /
`local_tools.browser.cjs` прошли. Браузер использовал отдельный backend и базы,
контролируемого автора и Edge. Реальная генерация GGUF и Windows installer
в рамках этого этапа не проверялись.

В исходном этапе не добавлялись фоновая очередь индексации, постоянный лексический индекс, новый
авторский процесс целевого документа, общий реестр результатов и внешние команды.
Существующие бюджеты обхода/контекста сохраняются. Цитаты не доказывают полный
охват и истинность. Структура сохраняется в извлечении/итоговом контексте;
существующий векторный индекс не мигрирует автоматически на поблочное хранение.
Ускорение и качество на реальной GGUF требуют отдельного измерения.

Дальнейшее обслуживание существующего индекса — проверка изменений, состояния
файлов, повтор ошибок и защита публикации ревизии — описано в
[workspace-index-maintenance.md](workspace-index-maintenance.md).
Последующий постоянный слой текста/позиций и лексических фрагментов описан в
[workspace-text-index.md](workspace-text-index.md); он сохраняет область и сверку.
