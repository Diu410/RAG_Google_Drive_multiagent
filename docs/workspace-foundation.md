# Workspace: первый проверяемый срез

Workspace — выбранная пользователем локальная папка, которая задаёт текущий
рабочий контекст ассистента. Доступ строго read-only: приложение показывает
файлы, позволяет переходить по директориям и читать безопасные текстовые
форматы, но не изменяет и не индексирует их автоматически.

## Ручная проверка

1. Из корня проекта запустите `npm run desktop:dev`.
2. В боковой панели нажмите **Выбрать workspace**.
3. В системном диалоге выберите тестовую папку с файлами и подпапкой.
4. Проверьте список, вход в подпапку и кнопку **Назад**.
5. Нажмите на `.md` или `.txt`: содержимое должно открыться прямо в Workspace.
6. Закройте окно Workspace и отправьте в чат: `Прочитай файл notes.md`.
7. Ответ должен содержать текст файла, а выполненная задача — действие
   `READ_FILE`. Команда `Покажи файлы в текущем workspace` создаёт действие
   `LIST_DIRECTORY`; для этого запроса локальная LLM не вызывается.
8. Перезапустите desktop-приложение. Выбранный workspace должен остаться в
   боковой панели.

Поддерживаются MD, Markdown, TXT, JSON, YAML, CSV и LOG до 1 МБ. Символические
ссылки отображаются, но переход по ним запрещён. Backend также
отклоняет абсолютные пути и `..`, поэтому навигация не выходит за выбранный
корень. Максимум за один запрос показывается 500 элементов.

## Границы этапа

Поиск, определение последней версии, автоматическая индексация, запуск файлов и
изменение данных будут добавляться отдельными проверяемыми срезами после
подтверждения этого UI.

Удаление документа из общей RAG-библиотеки повышает knowledge epoch. Старые
сообщения остаются видимыми в чате, но ответы, основанные на удалённых документах,
больше не передаются модели как скрытая история следующего запроса.
