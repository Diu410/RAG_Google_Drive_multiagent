# Время ответа локальной 9B и сохранение описания

В наблюдавшемся запросе готовый содержательный черновик появился примерно за
68 секунд, но показанный ответ сформировался через 19 минут 39 секунд.
Проверка и исправление заняли около 837 секунд, дополнительное восстановление
— ещё 260. HTTP read timeout не ограничивал общую длительность: сервер
продолжал отдавать токены, а каждый новый этап начинал ожидание заново.
История и журнал прочитаны через SQLite `mode=ro`, без исправления сохранённых
сообщений. Частные снимки и замеры находятся в `.user-evaluation/`.

## Общая цепочка обзорного ответа

Обзор workspace, включая «кто такой», у локального структурированного
провайдера подготавливается через `OverviewSynthesizer` / `FactFirstOverview`.
Отдельного маршрута с одним именем или ролью нет.

1. Подготовка тематического контекста сохраняет прямое описание говорящего.
   Модель предлагает до восьми содержательных предложений на весь обзор:
   роль, черты, цели, отношения и условия из текста. Один источник может
   заполнить весь бюджет; сервер учитывает уже проверенные предложения при
   отборе нового пакета, чтобы не тратить аудит на сведения, которым не осталось места.
2. Вместо переписывания длинных цитат модель сначала выбирает `evidence_id`
   из списка точных исходных предложений, затем формулирует предложение по
   выбранной цитате. `facts` — объект: ключ является ID цитаты, значение —
   одним предложением. Одна цитата не заполняет весь пакет разными пересказами.
   Необязательные свойства и `additionalProperties=false` ограничивают ключи
   допустимыми ID; число доступных ключей ограничено оставшимся бюджетом обзора,
   общий лимит дополнительно применяет сервер, поскольку
   `maxProperties` не входит в поддерживаемые ограничения текущего GBNF-парсера.
   Сервер разрешает ID только в текущем документе,
   проверяет происхождение цитаты и передаёт полный контекст смысловому аудиту.
   Неизвестный ID отклоняется. Выбор ID сам по себе не доказывает предложение.
   Ключи цитат последовательно нумеруются после помещения прямого упоминания
   темы и явных слов говорящего в начало: после вводного предложения GBNF допускает остальные цитаты,
   в том числе предшествующий контекст, признаки и намерения.
3. Аудит независимо проверяет субъект, действие с объектом, модальность и
   относимость. Пакет содержит до двух изолированных утверждений. Старые
   защиты адресата, говорящего, примера, направления отношения и модальности
   остаются. Цитата отдельного предложения не смешивает слова персонажа
   с соседним советом неназванному адресату.
   Полностью скопированное сравнение для разных утверждений и разных цитат
   делает пакет недействительным; такие утверждения проверяются по одному.
4. FAST и BALANCED показывают неизменённые проверенные предложения абзацами.
   Явные «называет себя», «заявляет» и «в письме» сохраняют атрибуцию без
   технического повторения имени файла перед каждой фразой. Для остальных
   предложений документальная рамка сохраняется. Источники доступны в ответе.
   Проверенные намерения и условия сохраняют собственную модальность;
   иллюстративный пример следует после описания предмета, а не вместо него.
5. REASONING может пересказывать проверенные сведения. Новый текст проходит
   независимую проверку; отказ или нехватка времени сохраняют исходные
   проверенные предложения. Нельзя наследовать оценку при новом пересказе.

Если модель не смогла корректно пересказать слова явно названного голоса,
сохраняется дословный исходный фрагмент как сообщение о тексте. Для этого
нужны отдельная проверка происхождения цитаты, положительная оценка относимости
и единственное прямое самоназвание по предмету вопроса вне примеров. Такая
цитата не наследует подтверждение отвергнутого пересказа и не считается новым
биографическим фактом. Самоназвание также может восстановить вводную фразу
перед уже проверенным объяснением; весь ответ не заменяется одной ролью.
Противоречивые самоназвания не выбираются произвольно. Это общее восстановление
обзора, не отдельный маршрут для «кто такой».

Провайдеры без `supports_evidence_ids` сохраняют контракт дословной цитаты
и границы 3/6. Рассуждение при аудите соответствует профилю: FAST/BALANCED
его не включают, REASONING оставляет отдельный бюджет для ответа. Только
нативная подготовка BALANCED получает короткое рассуждение на 128 токенов,
чтобы сохранить действующих лиц и условия в пересказе. FAST обходится без него.
Полный контекст источника сохраняется для аудита; набор допустимых цитат
ограничен бюджетом ответа, чтобы не переписывать весь файл в JSON.
При обычной генерации провайдер также задаёт конечный бюджет рассуждения,
если вызывающий код не передал его явно.

Для старого пути обзора уже проверенная содержательная часть сохраняется
до попытки исправления. Успешный обзор не проходит заново извлечение
самоназвания. Большой привлекательный черновик не считается целиком верным:
условный пример не превращается в свойство персонажа, метафора — в способность,
а неопределённое происхождение — в установленный факт.

Защита адресата отдельно различает «если ты …, то я …»: условное действие
явно названного говорящего не приписывается адресату. Нужны сохранённое условие
в ответе, совпадающие названные субъекты и явная привязка голоса к имени.
Сам субъект, действие и модальность всё равно проходят модельный аудит;
анонимное «я» и потерянное условие не получают такой корректировки.

Служебная запись субъекта «Говорящий (Имя Фамилия)» сравнивается по явно
указанному имени, без приписывания имени анонимному голосу. Отчёт «сообщает
адресату, что …» сохраняет документальную модальность наравне с «сообщает,
что …»; адресат остаётся получателем сообщения, а не автором самоназвания.

## Бюджет времени

| Профиль | Общий бюджет модельной цепочки | Один вызов |
| --- | ---: | ---: |
| FAST | 120 секунд | 90 секунд |
| BALANCED | 180 секунд | 90 секунд |
| REASONING | 240 секунд | 120 секунд |

`GenerationScope.deadline` создаётся для активной задачи и переносится в
`asyncio.to_thread`. Последующие модельные вызовы используют тот же срок.
Очередь до начала задачи и старт модели в отдельном замере не являются
измерением генерации. Файловые операции и сохранение истории не прерываются
по модельному бюджету.

Провайдер проверяет истечение времени и при пустой очереди, и при продолжающемся
потоке. Закрывается конкретный HTTP-поток; сервер модели и другие задачи не
останавливаются. Истечение времени — `GenerationDeadlineExceeded`, а не
пользовательская отмена. Неполный JSON не принимается, истёкший аудит не
перезапускается с новым сроком. Готовые независимые оценки сохраняются при
истечении времени на следующем элементе; непроверенные сведения не получают
статус `SUPPORTED`. При отсутствии проверенных сведений показывается
техническая причина, а не ложное сообщение об отсутствии информации.

Настройки в `api/.env.example`: `LLAMA_FAST_REQUEST_SECONDS`,
`LLAMA_BALANCED_REQUEST_SECONDS`, `LLAMA_REASONING_REQUEST_SECONDS`,
`LLAMA_GENERATION_SECONDS`, `LLAMA_REASONING_GENERATION_SECONDS`.
Значения должны быть конечными и положительными. `LLAMA_REQUEST_TIMEOUT`
остаётся отдельным HTTP-таймаутом. Бюджеты профилей можно переопределить через
`LLAMA_PROFILES_FILE` полями `request_seconds` и `generation_seconds`.

## Проверка

Обычный черновик, включая прямые вопросы об адресате, также использует
компактные ID предложений и цитат. Завершённые оценки сохраняются при
истечении времени в следующей части; итог не заменяется техническим отказом,
если уже проверены подходящие целые предложения. Подробности и границы —
[partial-answer-checks.md](partial-answer-checks.md).

`tests/test_response_latency.py` проверяет истечение времени на непрерывном
потоке токенов и на общем сроке, закрытие потока, отличие от отмены, отсутствие
нового запроса после срока, разрешение ID в точную цитату, отказ неизвестного ID,
независимый смысловой аудит и содержательный обзор без повторного черновика.
Проверки источников и защиты от неверных утверждений остаются обязательными.

Реальный замер использует отдельный собственный процесс 9B, тот же пакет
четырёх источников и отдельную временную базу. Рабочая конфигурация, модельный
выбор, документы и история не изменяются; собственный сервер останавливается
после измерения. Старт и прогрев отделены от времени ответа. Это проверка
цепочки генерации и доказательств на фиксированных источниках, а не замер
живого retrieval, desktop или надёжного p95.

Финальный замер модельного этапа Qwen 3.5 9B Q4_K_M, контекст 4096:
**161,69 секунды, 7 вызовов**, включая отдельные проверки после отказа пакета.
Ранние варианты занимали 94–156 секунд, но пропускали важные сведения или
ошибались в направлениях отношений; их время не выдаётся за замер финальной
подготовки. Обработка прямых цитат и восстановление вводной фразы добавлены
после измерения и проверены повтором всех семи сохранённых ответов модели.
Новых вызовов для этих операций нет. Итог сохраняет семь проверенных сообщений
о тексте: роль, черты, намерения, отношения, условие и отдельно обозначенный
пример из заметки. Два трудных пересказа представлены исходными
цитатами. Статус `SUPPORTED` означает проверку показанных сообщений, не
доказательство полной биографии или безошибочности самой модели-аудитора.

Весь набор backend-проверок: **402 теста, OK**. Частный файл сравнения
`.user-evaluation/draft-review-2026-10-10/answer-preview.md` содержит исходный
черновик и новый ответ. Сам снимок источников и журнал не добавляются в Git.

Формат с необязательными полями сверялся с
[парсером JSON Schema llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/common/json-schema.cpp)
через Context7. Поведение установленной версии проверяется реальным повтором,
а не только описанием последнего исходного кода.
