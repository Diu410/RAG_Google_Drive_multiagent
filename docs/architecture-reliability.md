# Надёжность индексов и выполнения задач

## Документы и восстановление

`DocumentService` управляет загрузкой, повторным импортом, переиндексацией и удалением. Повторный импорт Google Drive использует идентификатор удалённого файла: обновляется существующий документ.

Производственный writer сохраняет имя, исходный текст, Drive ID и решение о завершении замены индекса в одной SQLite-транзакции через callback `commit`. Если запись источника не удалась, новая ревизия векторов откатывается, а старый источник сохраняется. Чанки и граф получают актуальное имя документа. Успешное изменение источника повышает knowledge epoch, чтобы ответы по предыдущей версии не оставались скрытой историей модели; видимые сообщения чатов сохраняются.

Замена векторов сначала создаёт новую ревизию. Старая удаляется после успешной записи. SQLite хранит журнал `index_operations` с состояниями `PREPARED` и `COMMITTED`; при запуске и перед поиском незавершённые операции восстанавливаются. При удалении журнал содержит исходные векторы, поэтому откат не требует доступной embedding-модели. Метаданные, исходный документ и граф удаляются одной транзакцией SQLite.

Неудачная запись графа рабочей папки не помечается успешной. Существующий граф сохраняется, а следующая синхронизация повторяет извлечение без повторного создания уже актуальных векторов. Неполный обход папки, ошибки доступа и ограничение количества файлов не приводят к удалению записей отсутствующих файлов.

Повторное извлечение графа использует сохранённые чанки и идентификаторы текущей ревизии Chroma. Windows junction-папки обрабатываются как символические ссылки: отображаются без возможности перехода, исключаются из обхода и отклоняются при чтении и открытии вложенных файлов.

## Смена embedding-модели

Коллекции хранят отпечаток модели: SHA-256 локального GGUF, размерность и версию предобработки. Для внешнего backend задаётся неизменяемый `EMBEDDING_MODEL_ID`. Совпадение размерности не позволяет смешивать разные модели.

При запуске приложение проверяет обе коллекции и при необходимости создаёт новые, заново вычисляя embeddings. Имена активных коллекций переключаются одной транзакцией только после успешной записи обеих. Идентификаторы чанков сохраняются для ссылок из графа. Ошибка сохраняет старые коллекции; незавершённые временные коллекции удаляет журнал восстановления. Предыдущие успешно переключённые коллекции сохраняются на диске.

Повторить миграцию можно кнопкой «Обновить поисковый индекс» в документах или запросом `POST /rebuild-search-index`. Для непомеченного старого индекса по умолчанию выполняется переиндексация. `EMBEDDING_LEGACY_ADOPT=true` позволяет явно принять старые векторы, только если их модель проверена. `EMBEDDING_BATCH_SIZE` задаёт размер пакета; при превышении серверного лимита токенов пакет делится с сохранением порядка.

## Поиск и контекст

Лексический индекс кэширует токены и списки документов по словам. Запись, удаление и миграция инвалидируют кэш. Запрошенный лимит учитывается при выборе кандидатов. Обзор рабочей папки передаёт сведения об охвате; неполный обзор сопровождается пояснением в ответе.

Явно выбранный файл ограничивает область поиска, а не положение выдержки:
`workspace_context.py` ранжирует дословные окна по вопросу внутри всего текста.
Для обзора или неизвестной лексики используется распределённая выборка, включая
конец файла. Окна имеют отдельные chunk ID и исходные диапазоны символов;
разнесённые выдержки не склеиваются в одну цитату. Вопросы по короткому файлу
получают полный текст. При неполном охвате ответ сообщает об ограничении.
Инструкции источника исключаются по полной строке до выдачи обрезанной выдержки.

Метаданные workspace и кеш извлечения используют общую ревизию `file_revision.py`:
идентичность файла, размер, mtime и время изменения метаданных. На Windows вместо
creation time используется `ChangeTime` из
[FILE_BASIC_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_basic_info)
через
[GetFileInformationByHandleEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex).
Если файловая система не возвращает это значение, ревизия включает хеш байтов.
На других платформах используется ctime. Извлечение проверяет ревизию до и после
чтения; изменившийся во время обработки файл не попадает в кеш. Колонка `revision`
добавляется миграцией без изменения исходных файлов и истории. Первый scan
существующей базы обновит ревизии; одинаковый хеш не требует новых embeddings.

Общий бюджет применяется ко всем вызовам языковой модели. Число токенов проверяется после применения серверного шаблона чата; если соответствующие endpoints недоступны, используется консервативная оценка по байтам UTF-8. Сначала сокращается старая история, затем источники. Слишком большой вопрос отклоняется с пояснением.

Внутренняя редактура получает дочерний scope с тем же task ID и сигналом отмены.
Его дедлайн раньше общего на `max(20, request_seconds * .35)` секунд. Если до
этого дедлайна осталось не более пяти секунд, новый этап не запускается.
Истечение дочернего срока не отменяет задачу: сохраняется предыдущий завершённый
текст и начинается сверка с исходным общим дедлайном. Динамическая калибровка
резерва по метрикам конкретной модели пока не реализована.

## Выполнение и интерфейс

SQLite и файловые операции выполняются вне цикла событий. Запросы одной сессии исполняются последовательно, включая обращения через идентификатор чата. При перезапуске незавершённые задачи получают состояние ошибки. Завершение Live гарантированно помещается в очередь; разрыв соединения отменяет производителя.

Жизненным циклом backend управляет FastAPI lifespan. Очистка выполняется также при частичном сбое запуска. Фоновая миграция embeddings отменяется и её ссылка сбрасывается; ошибка `provider.close()` или остановки chat-сервера не препятствует попытке остановить embedding-сервер. Обработчики `on_event` не используются.

При разрыве Live-соединения отменяются также ожидающие записи токенов из фоновых потоков. Производитель не пытается поставить маркер завершения в очередь, которую отключённый клиент уже не читает. Тайм-аут публикации токена отменяет ожидающую запись и генерацию вместо потери токенов.

Удаление чата очищает сессию, задачи, действия, ожидающие планы и историю. Метка удалённого чата блокирует позднее сохранение или возобновление. Чат с выполняющейся задачей возвращает конфликт до её завершения или отмены.

Состояние чатов и опрос готовности моделей выделены в отдельные React hooks. Markdown с формулами и компоненты графа загружаются по требованию.

Смена workspace атомарно очищает прежние активный файл и каталог, если новые
значения не переданы явно. В той же папке обычный диалог сохраняет выбранный
файл. При обновлении списка чатов полная локальная история переиспользуется
только для не более новой серверной версии. Новая сводка инвалидирует её;
активный чат получает актуальную детализацию. Это также действует при пагинации.

## Границы применения

Блокировки индексов и сессий рассчитаны на один процесс API локального приложения. Для нескольких процессов потребуется межпроцессная координация операций и задач. Автоматические проверки используют временные базы, реальную временную Chroma и имитацию ответов моделей; качество генерации настоящей модели, доступ к Google Drive и упаковка Tauri требуют проверки в соответствующем окружении.
