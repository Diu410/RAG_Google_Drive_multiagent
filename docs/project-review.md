# Ревью проекта

Актуальное ревью безопасности и очистка от 10 октября 2026 года:
[отчёт](security-review-2026-10-10.md). Ниже сохранён первоначальный отчёт.

Дата: 2026-10-04. Проверены потоки документов и индексов, файловый доступ
workspace, выполнение задач, Live-транспорт, хранение чатов, API-клиент и
сборка интерфейса. Ниже перечислены подтверждённые проблемы и внесённые исправления.

Этот отчёт описывает первоначальное ревью. Старые тесты затем были удалены
по запросу пользователя и заменены новым набором. Текущие проверки реальных
локальных моделей и повтор оставленного чата описаны в
[проверке запросов](user-query-evaluation.md), исправления выбора инструментов —
в [tool-routing.md](tool-routing.md). Приведённые ниже числа старых тестов
относятся к первоначальному ревью.

## Проверка

Результаты ниже относятся к ревью до удаления тестов. По последующей просьбе
пользователя все проектные тесты, вспомогательные smoke/evaluation-скрипты,
конфигурация Playwright и команды их запуска удалены.

- Исходный полный набор: 260 Python-тестов, успешно.
- После исправлений: 265 Python-тестов, успешно; используются временные базы
  и модели-заглушки. Проверяются в том числе отказ записи источника, сохранение
  старой ревизии, повторное построение графа и отключение заполненного Live-потока.
- После исправления жизненного цикла добавлены три проверки: обычный запуск/
  остановка, частичный сбой запуска и ошибка закрытия провайдера.
  Полный набор из 268 Python-тестов прошёл успешно. Переход проверен
  по [документации FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events)
  и [тестированию событий](https://fastapi.tiangolo.com/advanced/testing-events).
- До удаления Playwright обнаруживал восемь браузерных тестов.
  Это была проверка доступности конфигурации и тестов; браузерные
  сценарии этой командой не выполняются.
- Четыре проверки поведения дополнительно запущены против исходных модулей из
  `git show HEAD:...`, загруженных в память. Они воспроизводят ошибки исходного
  кода; файлы рабочего дерева при этой проверке не подменялись.
- Проверка TypeScript прошла. Production-сборка Vite прошла через JavaScript API
  с `configFile: false` и тем же React-плагином. Параметры взяты из текущего
  `frontend/vite.config.ts`; настройки server относятся только к dev-режиму.
  API проверен по [документации Vite 6](https://v6.vite.dev/guide/api-javascript).
- Обычная `npm --prefix frontend run build` остановилась при загрузке конфигурации:
  esbuild не смог прочитать родительский каталог из-за ограничений доступа среды.
  Конфигурация проекта ради этого ограничения не менялась.
- Форматирование изменений проверяется через `git diff --check`.

## Границы проверки

Desktop installer, реальные GGUF-модели, Google Drive OAuth, качество распознавания
и TTS не проверялись end-to-end. Junction-тест моделирует соответствующую
проверку `Path.is_junction`, без создания системной ссылки. Браузерные сценарии
не запускались: они ожидают готовый интерфейс на `http://127.0.0.1:8001`
и установленный Microsoft Edge.

API рассчитан на локальное использование одним процессом. Добавление сетевого
доступа или нескольких процессов требует отдельной задачи на аутентификацию и
межпроцессную координацию.

## Повторное ревью последних запросов «Тест 4» на 9B

Журнал двух последних завершённых задач показывал успешный поиск документов
и генерацию черновика, затем отказ проверки с предупреждением о контексте.
Воспроизведена ошибка жизненного цикла подсчёта токенов: неудачное обращение
к tokenizer до загрузки сервера сохраняло `_tokenizer_available=False` навсегда.
Кроме того, оценка по байтам UTF-8 сохранялась в кеше как точный подсчёт.
Готовность модели после загрузки не восстанавливала корректную проверку.

На том же запросе проверки при контексте 4096 и резерве ответа 1200 токенов
временная оценка давала 15 670 токенов вместо реальных 2452. Даже после удаления
всех источников оценка оставалась 8626. Поэтому приложение удаляло доказательства
из входа проверки, хотя полный исходный запрос помещался. Это воспроизводится
на готовой 9B без изменения весов модели, если предварительно вызвать подсчёт
до запуска сервера. Предыдущая оценка ожидала готовности сервера перед первым
подсчётом и не проверяла эту последовательность.

Исправления:

- Временные оценки не кешируются; следующие подсчёты снова обращаются к tokenizer.
  Успешные точные результаты продолжают кешироваться.
- Отказ бюджета проверки имеет статус `UNAVAILABLE`. Workspace сохраняет
  техническую причину в финальном ответе и журнале и не повторяет синтез.
  Ошибка больше не превращается в отсутствие сведений или просьбу уточнить вопрос.
- Из уже проверенного обзора сохраняются целые подходящие предложения,
  даже если все утверждения подтверждены, но одно признано посторонним.
  Такой случай больше не требует повторной генерации всего объяснения.

Новые регрессии проверяют восстановление после HTTP 503, ошибки соединения
и некорректного ответа tokenizer, повтор того же prompt, сохранение причины
отказа бюджета и использование проверенной части обзора. Полный offline-набор:
278 тестов после дополнительной проверки смыслового аудита, успешно. Приватные журналы и модельные повторы находятся в
игнорируемой `.user-evaluation/latest-review/`; результаты реальной генерации
описываются отдельно в `user-query-evaluation.md`.

Повтор также выявил ошибку самой проверяющей 9B: она признала одинаковыми
противоположные направления отношения власти. Добавлена узкая защита для
явных русских конструкций с «подвластен/подвластно»; смешанные формулировки
и отрицания не получают автоматического вердикта. Эта защита только отклоняет
противоречивое утверждение и не подтверждает остальные свойства персонажа.

В парном модельном опыте правильный пересказ слов говорящего сначала получил
ложный отказ: 9B классифицировала сообщение о тексте как факт реального мира.
Для явно атрибутированных слов в документе совместимость с `SELF_DESCRIPTION`
теперь проверяется отдельно от этой ошибочной метки. Примеры самовнушения
исключены; совпадение субъекта, действия, буквальная цитата и привязка говорящего
остаются обязательными. В журнале сохраняются исходные поля модели и отдельная
причина грамматического отказа или восстановления модальности.
