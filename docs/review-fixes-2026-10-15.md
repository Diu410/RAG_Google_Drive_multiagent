# Исправления ревью и внутренняя редактура

Исправления относятся к текущему рабочему дереву. Существовавшие изменения,
история пользователя, документы, GGUF, `.env` и credentials сохранены.

## Пользовательский сценарий

Ручная пошаговая мастерская и переключатель режима редактуры удалены из чата.
Интерфейс отправляет обычные вопросы по источникам с `use_multi_agent=true`.
Библиотека и workspace используют одну внутреннюю редактуру в
`api/answer_editing.py`; повторного поиска или перехода между источниками нет.

После генерации FAST делает одну редактуру; BALANCED/REASONING могут выполнить
улучшение и сборку. Перед каждым этапом остаётся резерв общего бюджета для
проверки. Неполная или неудачная редактура сохраняет предыдущую завершённую
версию. Итог проходит обычную контекстную или строгую проверку по тем же
источникам. Журнал содержит `EDIT_RESPONSE`, `ENHANCE_RESPONSE`, `MERGE_RESPONSE`
и готовые тексты этапов. Пользователю не нужно подтверждать промежуточные версии.
Live сохраняет свой короткий путь; чтение файла и системные операции не
превращаются в литературную редактуру.

Старые `/agent/*` сохранены для API-совместимости. `workspace_id` в draft теперь
обрабатывается Core; edit/enhance/merge могут получать исходный вопрос и контекст.
В основном интерфейсе эти маршруты не используются.

## Доступ к API и файлам

`LocalAccessMiddleware` проверяет loopback Host, допустимый Origin и
`X-Fortuna-Token` до вызова чувствительного обработчика. Токен создаётся на
запуск; desktop получает его из Rust через IPC и передаёт backend через
переменную процесса. Он не попадает в URL, React bundle, Git или localStorage.
`/api/health` доступен без токена для readiness.

Web/dev получает токен через `GET /access-token` с обязательным
`X-Fortuna-Client: web`; обычные межсайтовые формы/скрипты такой доступ не получают,
Origin и Host проверяются. В desktop HTTP-выдача токена запрещена.
При смене токена после dev-reload web-клиент повторяет инициализацию один раз;
запрос с неверным токеном до обработчика не доходит.
Отдельные локальные клиенты должны передавать токен; для автоматизации можно
инъецировать `KONTUR_API_TOKEN` в окружение запуска. Это защита локального
приложения от посторонних запросов браузера, а не многопользовательские роли
или изоляция от процессов, уже имеющих доступ к аккаунту ОС.

Открытие через системное приложение ограничено явным списком документных и
медиаформатов. Программы, скрипты, ярлыки и неизвестные расширения отклоняются.
Чтение и индексирование исключают типовые имена credentials, `.aws`, `.ssh`,
`.gnupg` и характерные поля ключей/токенов в первых 64 КиБ конфигурационных
файлов. Это не универсальное обнаружение всех секретов в произвольном тексте.
Существовавшие секретные векторы исключаются проверками свежести и чтения;
при следующей синхронизации удаляются из индекса workspace.
INFO-превью страниц и распознанной речи удалены.

Историческая строка Google API key требует отдельного отзыва у провайдера.
Права к аккаунту Google Cloud в этой задаче не предоставлены; отзыв не заявляется.
Git не переписан, поскольку переписывание не отзывает ключ и затронуло бы
существующую историю. `scripts/check_secrets.py` и CI предотвращают новые
совпадения в отслеживаемых исходниках, не печатая значения.

## Ограничения извлечения

ASGI ограничивает размер тела до form-парсера, включая поток без Content-Length.
Upload принимает только multipart; urlencoded не попадает в его парсер.
JSON ограничен 8 МиБ по умолчанию. Форматы запросов `/agent/*` также ограничены.

Общие настройки в `api/.env.example` задают лимиты XML DOCX, итогового текста,
страниц PDF, растеризации OCR, времени и числа одновременных извлечений. OCR
получает собственный timeout. Проверки времени между операциями кооперативные:
нативные PDF/XML-парсеры ещё не изолированы отдельным процессом с принудительным
лимитом памяти. Работа со специально повреждёнными нативными форматами не
считается полностью изолированной песочницей.

Отказ OCR или полноты PDF больше не подменяется частичным текстовым fallback.
WorkspaceDocumentReader при превышении лимита отказывает вместо тихого обрезания.
Drive ограничивает скачивание, суммарные байты, глубину, число файлов и время;
у HTTP-транспорта есть timeout. Частичный импорт возвращает `status=partial`,
`failed`, `limited`, а UI перечисляет пропущенные файлы. Успехи сохраняются,
неудачная замена сохраняет прежнюю ревизию.

## Ответы, история и отмена

Backend одной SQLite-транзакцией записывает ответ в `workspace_chats`, контекст
в `application_logs`, результат в `assistant_responses` и завершение задачи.
Успех больше не зависит от второго PUT браузера. `request_id` связывает ответ
с сообщением пользователя и возвращает уже завершённый результат при повторе.
Другой вопрос или источник с тем же ID отклоняется. Номер версии чата защищает
от устаревшего сохранения; прежние API без номера версии сохраняют совместимость.

`GET /chats/page` возвращает компактные страницы по 50 диалогов, курсор и поиск
по всем названиям с Unicode casefold. `GET /chats/{id}` читает сообщения одного
диалога. Прежний `GET /chats` сохранён, с лимитом/offset. Контекст модели
ограничивается в SQL последними тремя парами сообщений.

Обычный UI использует `/assistant/stream`, который рано передаёт ID задачи,
сохраняя `live_mode=false`. Промежуточные генерации не транслируются как итог.
«Стоп» закрывает поток и отменяет задачу. При обрыве после фиксации результата
UI восстанавливает ответ из чата без новой генерации. Live совместим с прежним
маршрутом; ответы workspace озвучиваются после получения готового результата.

## Перенос данных

`api/data_migration.py` делает SQLite backup с учётом WAL, проверяет quick_check
и сначала копирует данные в собственный staging. Пока снимается копия, SQLite
источника удерживается от новых записей. Незавершённые задачи/операции индекса
требуют предварительного восстановления в старом приложении. Перенос не выполняет
запись в рабочие таблицы источника и не удаляет его файлы.

Журнал `.legacy-migration.json` различает копирование, публикацию и завершение.
Обрыв копирования повторяет staging, обрыв публикации продолжает тот же снимок.
Существующая пользовательская база не перезаписывается и не объединяется с
чужим Chroma. Установки, уже повреждённые старым переносом и не имеющие журнала,
нельзя автоматически отличить от самостоятельных пользовательских данных;
неоднозначные данные сохраняются для отдельного восстановления.

## Проверка

`tests/test_review_fixes.py` содержит 35 изолированных регрессий: API, CSRF/Host,
bootstrap desktop/web, потоковые лимиты, opener, credentials, PDF/DOCX, журнал,
атомарное сохранение, повтор запроса, версии, пагинация, WAL и прерывание
миграции, внутренняя редактура и проверка её итогового текста.

`tests/review_fixes.browser.cjs` использует production UI и отдельный HTTP fixture:
токен, страницы истории, отсутствие мастерской, готовый ответ, обрыв после
сохранения, отмена обычного ответа и перезагрузка. Личные API/файлы и модели
не используются. `tests/graph_workbench.browser.cjs` обновлён для нового клиента.
Для браузерных скриптов нужен установленный Playwright и Edge;
`PLAYWRIGHT_MODULE_PATH` при необходимости указывает на модуль Playwright.

`.github/workflows/checks.yml` запускает проверку секретов, backend-тесты и
обычную frontend-сборку в Windows CI. Удалённый запуск CI в этой задаче не
заявляется. Installer, настоящий OAuth и новые реальные GGUF-замеры требуют
отдельных проверок; заглушки не доказывают качество конкретной модели.

Итоговые локальные результаты:

- 505 backend-тестов — успешно, 81,745 с; из них 35 новых регрессий этого этапа.
- Оба браузерных сценария — успешно на production-сборке и HTTP/API fixtures.
- TypeScript и `cargo check --locked --offline` — успешно.
- Production frontend собран через Vite JavaScript API с исходным React plugin.
  Штатный `npm run build` в данной среде ограничен чтением родительского каталога
  при загрузке конфига; исходный Vite-конфиг ради этого ограничения не менялся.
- `git diff --check`, проверка секретов отслеживаемых исходников и сценарий
  воспроизведения старых проблем — успешно. Воспроизведение теперь показывает
  отказы чужих Origin/Host, отсутствие вызова form-парсера для urlencoded,
  запрет запуска `.cmd` и отказ от неполного PDF/переполненного DOCX.
- Временный сервер браузерной проверки остановлен; рабочие модели и backend
  пользователя не запускались и не останавливались.
