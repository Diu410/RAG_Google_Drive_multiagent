# Продолжение N1: открытие созданного документа

В новых сообщениях «Испытание N1» документ сохранялся, но следующая просьба
«открой его» читала другой файл. Даже явное имя созданного файла открывало
другой документ. Вопрос о выполненном действии снова запускал чтение,
а повторная просьба открыть созданный документ попадала в создание.

## Причины и исправления

- Местоимение разрешалось моделью как ссылка на обсуждаемое лицо.
  Прямые просьбы открыть/прочитать активный документ теперь выполняются
  по сохранённому пути до переписывания истории и планирования моделью.
- Старая текущая подпапка исключала точное совпадение имени в корне.
  Неявная папка теперь служит предпочтением среди совпадений; явно указанная
  папка остаётся ограничением. Отсутствующее буквальное имя с расширением
  не подменяется ни лексически похожим файлом, ни модельным выбором.
- После записи не обновлялась текущая папка сессии. Сохранение теперь
  возвращает активный файл и его родительскую папку, включая пустой путь корня.
- Причастие «созданный» разрешало категорию записи. Проверка полномочий
  отличает формы просьбы от причастий и прошедшего времени.
- Для «созданный тобой документ» добавлено чтение успешных эффектов из журнала
  этого чата и workspace. Позднее чтение/редактирование другого файла и короткая
  история не теряют результат. Учитываются конвертация и сохранение после
  отдельного подтверждения предпросмотра. Неприменённые предложения исключаются.
  Новый результат apply хранит тип операции; старый журнал читается по прежнему
  контракту: применённая правка имеет резервную копию, создание — нет.
- «Что ты открыл?» возвращает реальный последний `OPEN_FILE` без нового открытия
  и чтения содержимого. Новая просьба открыть файл заменяет ожидающее уточнение
  параметров конвертации. Удалённый результат не заменяется другим документом.

Изменены `assistant_core.py`, `assistant_repository.py`, `command_intent.py`,
`workspace_intent.py`, `workspace.py`, `local_tool_intent.py`,
`local_tools_skill.py`, `workspace_documents.py`. Общая библиотека и Google Drive
сохраняют прежние маршруты. Содержимое существующего чата не переписывается.

## Проверки

`test_created_document_followup.py`: **20/20**. Проверяются реальные файлы,
SQLite и открытие через перехваченный системный opener: местоимения,
явное имя, устаревшая папка, одинаковые имена в разных папках, отсутствие
точного файла, удаление результата, подтверждение предпросмотра другим ходом,
конвертация, отсутствие сохранения предпросмотра, независимость чатов/workspace,
отрицание и цитирование команд. Разрешитель истории и планировщик не вызываются.

Итоговый полный набор: **630/630**, 105,1 секунды. Журнал:
`.user-evaluation/document-followup-unit.log`. `git diff --check` пройден.

Браузерный прогон с production UI, реальным изолированным backend и файлами
пройден: создание → открытие по местоимению → открытие по имени → отчёт
о действии → чтение другого файла → открытие созданного. Дополнительно проходят
прежние правка/резервная копия, PDF, предпросмотр, отмена, авторизация,
устаревшая запись и граница workspace. Проверка ждёт новый ответ, даже когда
его текст совпадает с предыдущим. Системные приложения не запускаются.
Артефакты: `.user-evaluation/agent-tools-browser-1792691300822/`.

## Повтор новых запросов из настоящего чата

`evaluate_document_followup.py --chat "Испытание N1"`: **4/4**.
Рабочая SQLite открыта в режиме `mode=ro`. В отдельную папку перенесены байты
созданного документа, ошибочно открытого документа и завершённые записи
создания из старого журнала. Ответы ассистента не служат источником пути.

| Запрос | Проверяемый результат | Секунды |
|---|---|---:|
| «открой его» | Путь реально созданного документа | 0,129 |
| Явное имя при старой вложенной папке | Точный файл в корне | 0,185 |
| «ты чё открыл» | Путь действительно записанного открытия | 0,150 |
| Повторная просьба открыть созданный документ | Созданный файл из старого журнала | 0,128 |

Ноль попыток обращения к модели; три ожидаемых вызова перехваченного opener.
Хеши рабочей базы, выбора модели, оригиналов и копий документов сохранились.
Код не менялся во время прогона. Полные ответы, действия и хеши:
`.user-evaluation/document-followup-20261022-204821/document-followup.json`.

Это измерение маршрутизации и подготовки действия; запуск системного приложения
перехвачен и в указанное время не входит. Прогон не переоценивает точность
развёрнутого обзора небольшой модели: прежний результат 7/8 из отдельного
описательного прогона остаётся в [предыдущем отчёте](agent-tools-n1-2026-10-22.md).
Проверены исходники и изолированный API с production UI; установленная
desktop-сборка в этой задаче не пересобиралась и не перезапускалась.
