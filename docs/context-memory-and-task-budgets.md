# Память диалога и длительность задач

Реализованы два независимых механизма: планирование времени задачи и
компактизация активного окна диалога. Полная история в SQLite сохраняется.
Ни длительность, ни память не расширяют полномочия инструментов: операции
по-прежнему проверяются по исходному запросу пользователя.

## Короткая и длительная работа

`task_policy.py` определяет категорию до генерации без дополнительного вызова LLM.

| Категория | Примеры | Общий бюджет по умолчанию |
|---|---|---|
| SHORT | Открыть/прочитать названный файл, сохранить готовый текст, приветствие | 45 секунд |
| STANDARD | Обычный вопрос и проверка ответа по источникам | FAST/BALANCED/REASONING: 120/180/240 секунд |
| LONG | Исправить код с тестами, создать авторский документ, обработать всю папку, выполнить зависимый план | До 540 секунд |

Для пересказа фактическое число частей уточняет бюджет: 18 секунд на часть,
24 при расширении, не меньше бюджета профиля и не больше общего предела LONG.
Дедлайн считается от исходного начала задачи. Повторная оценка, сообщения
прогресса и продолжающийся поток токенов не продлевают его.

Отдельный вызов модели сохраняет свой прежний предел, процесс проверки —
45 секунд, агент — максимум 10 решений. Длительная задача не становится
одним неограниченным запросом. UI получает промежуточные статусы. Статусы
под нагрузкой могут пропускаться; итоговый ответ и токены сохраняют отдельный
протокол доставки. Отмена останавливает собственную генерацию/процесс.

Общий таймаут возвращается как обычный сохранённый ответ с
`plan_status=INCOMPLETE`. Выполненные файловые эффекты перечисляются из журнала;
незавершённое не считается выполненным. `task_status=COMPLETED` обозначает
завершение обработки запроса, а не достижение всех целей. Прочие ошибки
провайдера и невозможность загрузить модель сохраняют свои сообщения об ошибке.

## Подход OpenCode и адаптация

Проверены [официальная конфигурация OpenCode](https://opencode.ai/docs/config/#compaction)
и [исходник компактизации](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/compaction.ts)
через Context7 и GitHub 23 октября 2026 года. Использованы принципы порогового
запуска, резерва контекста, checkpoint и сохранения свежей части разговора.
Численные резервы больших моделей не перенесены в наше окно 4096 токенов.

В Фортуне применяется извлекающая сводка. Модель выбирает до шести ID
исходных пользовательских фрагментов. В память попадают соответствующие
дословные тексты; сгенерированный пересказ не становится новым фактом.
Упоминания ограничений и явных изменений решений выделяются отдельно от
модельного выбора. Отрицания, версии, пути и расширения остаются дословными.
Этот отбор эвристический, а не универсальная семантическая оценка важности.

## Подготовка окна

1. Читаются новые исходные реплики после checkpoint. Архив загружается
   страницами; при большом отставании есть ограничение обработки и явный
   `backlog_remaining`.
2. Токенизатор сервера оценивает окно. Для истории доступно до 28% контекста
   с дополнительным учётом текущего вопроса и резерва под инструкции/ответ.
   При недоступном токенизаторе используется помеченная консервативная оценка
   по UTF-8, которая не выдаётся за настоящий подсчёт токенов.
3. Пока окно помещается, вызова модели-компактора нет. После превышения
   сжимается старая часть; последние реплики остаются рядом со сводкой.
4. Вызов выбора ID ограничен 12 секундами. При неверном JSON, неизвестном ID,
   обрыве или недоступной модели применяется извлекающий fallback с явной меткой.
5. Перед сборкой prompt сокращаются объёмные старые ответы. Ограничения
   остаются отдельно. Если даже они не помещаются, возвращается незавершённый
   результат; молчаливого обрезания ограничения нет.
6. Только после проверки размера сохраняется новый версионированный checkpoint.
   Конкурирующая устаревшая запись не заменяет более свежую.

Для актуального вопроса выполняется ограниченный буквальный поиск оригинальных
реплик, включая простые варианты регистра кириллицы. Поэтому старый факт можно
поднять, даже если компактор его не выбрал. «Что я просил…» использует диалог,
а явно названные документы сохраняют документальный маршрут. Поиск не является
полноценным семантическим поиском и может не найти косвенную отсылку.

Прямое чтение/открытие и полностью заданные файловые команды обходят менеджер
памяти. Буквальное сохранение предыдущего ответа берёт полный текст отдельно
от сокращённого prompt. Обновление индекса исключает старые ответы ассистента
из фактического контекста; явная просьба скопировать их дословно остаётся возможной.

## Хранение и области

`application_logs` не заменяется сводкой. В одной транзакции с ответом
`assistant_history_scopes` записывает область новых реплик.
`assistant_context_checkpoints` содержит курсор, выбранные цитаты, ограничения
и версию, отдельно для session/workspace/эпохи знаний. Пользовательские реплики
сохраняются при смене эпохи; старые ответы ассистента не возвращаются как факты.

У прежних записей область неизвестна: `assistant_context_origins` закрепляет
их за первой областью использования после обновления. Это совместимость,
не восстановление неизвестной исторической области. В другой workspace такие
записи не переносятся. Удаление чата очищает checkpoint, origin и привязки истории.

`task_policy` и `context_memory` доступны в ответе и сохранённом сообщении.
В UI видны длительная работа и факт компактизации. Модельная сводка остаётся
контекстом разговора, а не доказательством фактов в документах.

Настройки: `SHORT_TASK_SECONDS`, `LONG_TASK_SECONDS`,
`CONVERSATION_COMPACTION_ENABLED`. Новых библиотек или моделей не требуется.

## Проверки 23 октября

Полный набор: **707/707**, 150,9 секунды. Сборка frontend и браузерный прогон
прошли. Браузер использует отдельные реальные API/SQLite/файлы и контролируемую
модель: проверяет индикатор компактизации, длительную задачу и корректное
завершение по таймауту вместе с прежними файловыми/репозиторными сценариями.

Реальный прогон Qwen 3.5 4B выполнен на отдельном синтетическом диалоге:
старое ограничение про Drive, давний код проекта и 36 объёмных посторонних пар.

| Запрос | Результат | Время с готовой моделью |
|---|---|---:|
| Что я просил насчёт Google Drive? | Дословное ограничение сохранено; окно 32973 → 805 токенов | 4,514 с |
| Что я говорил о коде проекта Нарвал? | Из оригинала восстановлен код 4817; окно 882 токена | 1,506 с |

Также прошли восстановление checkpoint новым менеджером, изоляция другого
workspace, сохранность оригинальных строк архива и хешей рабочей базы/выбора
модели. Исходные 33 тысячи токенов относятся к контрольной истории; они не
помещались бы в окно 4096. Это проверка компактизации и восстановления сведений,
а не замер ускорения старой реализации с таким prompt.

Команды:

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe tests/benchmark_context_memory.py
npm --prefix frontend run build -- --configLoader runner
node tests/local_tools.browser.cjs
```

Подробные приватные артефакты находятся в `.user-evaluation/`; отчёт реального
прогона — `20261023-113129/context-memory-report.json`, общий тестовый журнал —
`context-all-complete.log`, браузерный — `context-browser-final.log`. Проверены исходники и собранный
web-интерфейс. Установленный desktop sidecar/installer не пересобирался.

Полный архив делает пропуски восстанавливаемыми, но не гарантирует включение
каждой важной детали в активный контекст. Общего фонового продолжения любой
задачи после перезапуска backend этот механизм не добавляет.
