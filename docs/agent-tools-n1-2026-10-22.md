# Инструменты из обычного чата: разбор N1

Чат «Испытание N1» прочитан из рабочей SQLite в режиме read-only. История и
личные документы не изменялись. Тексты и цитаты сохранены только в игнорируемой
`.user-evaluation/`; здесь описаны общие ошибки без содержимого личных файлов.

## Обнаруженные причины

Просьба создать новый документ с описанием предмета не содержала заранее
выбранного имени и готового текста. Прежний `local_tools` распознавал только
полные команды нескольких форм, а исполнитель повторно требовал тот же
буквальный шаблон. Общий маршрутизатор workspace знал только чтение. Поэтому
понятная просьба попадала в уточнение о списке и чтении файлов.

Узкое уточнение о принадлежности титула разрасталось до причин и обязанностей.
История использовалась для разрешения местоимения, а затем предыдущий ответ
с неподтверждёнными утверждениями повторялся генератору как сообщение assistant.
Это помогало переносить прежние ошибки в следующий ответ. В проверке одна из
цитат описывала адресата, а не названного говорящего.

В описании смешивались слова говорящего, советы адресату и пример для
проговаривания. Модель могла ошибочно назвать субъект документом и подтвердить
пример как самописание лица. Одна только положительная модельная метка здесь
недостаточна.

## Что теперь выполняет агент

`LocalToolsSkill` — зарегистрированный навык с конкретными контрактами:
`create_document`, `convert_document`, `edit_document`, `search_text`,
`read_lines`, `repository_overview`. `local_tool_intent.py` разрешает цель и
параметры обычной просьбы через типизированную схему. Полные буквальные просьбы
сохраняют быстрый маршрут. Не требуется знать названия операций или заполнять формы.

Примеры пользовательских задач:

```text
Создай в этой директории документ, который опишет наш проект
Мне нужен PDF этого документа, чтобы отправить его коллеге
Сохрани предыдущий ответ отдельной заметкой
Можешь в Заметка.md поменять «4817» на «6248»?
Где встречается фраза «Код: 6248»?
Покажи структуру проекта
Предпросмотр: конвертируй Заметка.md в PDF
```

Создание по теме включает свежий поиск, написание, редактуру и проверку. При
частичной оценке в новый документ допускаются только целые уже подтверждённые
предложения с действительными доказательствами. Для самостоятельного описания
лица предложенные примеры от первого лица исключаются из генерационного вида;
оригинальные источники сохраняются для сверки. Явный разбор примеров использует
полный контекст. Без подтверждённого содержимого файл не создаётся.

Имя нового документа можно подобрать по теме. При создании «здесь» используется
выбранная в браузере папка, переданная как `workspace_directory` и проверенная
по корню workspace. Модель не выбирает другую папку вместо неё. Неуказанное
имя получает свободный суффикс; явно заданный существующий путь не перезаписывается.
«Этот документ» использует активный файл, явно названный источник приоритетнее.
Неизвестный параметр можно сообщить следующим ходом.

Явная просьба выполняется без повторного разрешения. Предпросмотр включается
по просьбе; тогда «да» применяет изменение, «отмена» отменяет. Сохраняются
проверки корня, формата, символьных ссылок, версий и резервные копии. Удаление,
переименование, запуск кода и произвольная перезапись новых файлов не добавлены.
Точная замена использует только буквальные old/new из пользовательской реплики.

Отдельные формы инструментов убраны из Workspace. Чат служит входом к тем же
файловым сервисам; окно папки сохраняет просмотр, навигацию и индексацию.

## Уточнения и доказательства

Разрешитель заменяет местоимение буквальным именем из истории с сохранением
структуры текущего вопроса. «Чего/чей» не заменяется причинами или обзором.
Для узкого вопроса используется краткий бюджет, а явная просьба подробности
сохраняет приоритет. Прежние ответы не повторяются генератору workspace;
их контекст уже обработал разрешитель ссылок. Пользовательские реплики остаются.

В коротком обзоре генератор получает тематические абзацы с контекстом,
проверяющий — все выбранные исходники. Рамка примера сохраняется из самого
исходника; инструкции генератору передаются отдельно от текста источников.
Нативные фрагменты упорядочиваются по
относимости, исходный текст каждого фрагмента и полный набор сохраняются.
Независимый аудит участников, действия, направления и модальности обязателен.
Отказ привязки адресата, модальности или примера передаётся точечному исправлению
с конкретной причиной. Новый текст проходит повторную проверку.

Дополнительная защита отклоняет признак, дословно заимствованный только из
предложенного примера для проговаривания, если ответ выдаёт его за самописание
лица. Это проверка происхождения признака, а не подтверждение по похожим словам.
Реальный такой же фрагмент вне примера отключает эту защиту, но не смысловой аудит.

При переполнении независимой сверки длинная цитата прежде дублировалась в
пакете утверждения и в тексте источника. Обрезка источника могла убрать часть
той же цитаты: это корректно давало `UNAVAILABLE`, но мешало сохранить даже
проверяемое описание. Для компактного провайдера добавлен запасной транспорт:
дословные выбранные фрагменты передаются один раз в `quotes` с ID и `chunk_id`,
окружающий текст — отдельно. Перед вызовом модели проверяются все ID и точное
присутствие каждого фрагмента. Если доказательства всё равно не помещаются,
результат остаётся `UNAVAILABLE`. После передачи по ID выполняется независимый
смысловой аудит; наличие ID не означает подтверждения.

Контроль с похожими именами выявил ещё одну ошибку модели: при заполнении
`claim_*` она иногда брала действие и модальность из источника. Исходное
утверждение в запасном транспорте длинных цитат повторяется после источников как отдельное поле запроса,
не как сведение документа. Явная подпись единственного автора речи от первого
лица сохраняется даже в конце файла. Прямое самоописание этого голоса нельзя
приписать соседнему адресату; правило только отклоняет несовпадение. Вложенная
цитата другого голоса, сообщение о другом лице и несколько подписей не
подпадают под это ограниченное правило и требуют обычной смысловой оценки.

Дополнительная ручная сверка выявила ложный успех автоматического повтора:
проверка наличия темы и модельного `SUPPORTED` не заметила приписывания примера
самовнушения персонажу. Этот результат не засчитан как точный. Критерии N1
дополнены независимыми запретами на обнаруженные ошибочные атрибуции. Для
короткого описания лица примеры самоутверждения теперь исключаются из материала
писателя так же, как при создании документа. Остальные тематические абзацы
сохраняются; проверка по-прежнему видит все исходники. Явный вопрос о примере
передаёт его исходный текст генератору.

## Проверки реализации

- 610 автоматических тестов — успешно; журнал
  `.user-evaluation/agent-documents-offline-final-grounding.log`.
- TypeScript и production-сборка frontend — успешно.
- Браузерный прогон в Edge — успешно: поиск, фактическое создание, замена с
  резервной копией, PDF с кириллицей, предпросмотр, применение/отмена,
  авторизация, устаревшая правка и границы workspace. Артефакты:
  `.user-evaluation/agent-tools-browser-1792676319141/`.
- Контроль контекста `.user-evaluation/20261022-175105/`: 8/8, четыре реальных
  вызова с ID длинных цитат, ноль ложных подтверждений и технических отказов.
  До изменения порядка данных диагностический вариант имел два ложных
  подтверждения; следующий вариант — одно. Все результаты сохранены, критерии
  ожидаемого вердикта не менялись. Объём длинного текста увеличен с 20 до 40
  нейтральных абзацев, чтобы действительно переполнить прежний транспорт.
  Эти прогоны не доказывают общей безошибочности небольшой модели.
- Проверка прежнего сложного набора: 16/16, включая восемь верных и восемь
  искажённых ответов. Артефакты `.user-evaluation/20261022-173635/`.
  Применение нового порядка данных ко всем аудитам давало 12/16 с четырьмя
  ложными отказами (`20261022-173157`); поэтому оно ограничено запасным
  транспортом длинных цитат, где требуется устранить дублирование.

## Итоговый повтор N1

`.user-evaluation/20261022-174810/`: **7/8** по усиленным критериям. Использована
локальная Qwen 3.5 4B Q4_K_M через уже работающий сервер. Индексация и прогрев
не входят во время вопроса. Исходные документы, рабочая база и выбор модели
сохранили хеши; Python-код не менялся во время прогона.

| Сценарий | Результат | Секунды |
|---|---|---:|
| Обычный обзор персонажа | Не пройден, `PARTIALLY_SUPPORTED` | 72,72 |
| Уточнение принадлежности титула | Пройден, `SUPPORTED` | 11,40 |
| Создание описания в выбранной директории | Пройден, файл сохранён | 26,89 |
| Косвенная просьба получить PDF активного документа | Пройден, содержимое проверено | 4,38 |
| Создание файла с готовым текстом | Пройден | 0,16 |
| Правка из обычной просьбы | Пройден, резервная копия создана | 3,95 |
| Поиск фразы с номером строки | Пройден | 0,15 |
| Структура проекта | Пройден | 0,14 |

Ошибочные самоописания из примера больше не вошли в итоговый обзор; это
проверено также вручную по источнику. Общий обзор всё ещё не считается точным:
он многословен, допускает неточности в участниках и условиях, а смысловая оценка
неустойчива для отдельных сообщений о совете и обязательстве. Замечания
остались в проверке; этот сценарий не засчитан. В создании документа сохраняется
отдельный уже проверенный текст, а прежний обзор не используется как факт.

Времена отражают отдельный прогон, не общий p95 и не обещание ускорения всех
ответов. Успешные файловые операции и контрольные пары не доказывают
безошибочности произвольного развёрнутого пересказа. Следующий предмет работы —
независимые критерии для каждого утверждения обзора, привязка советующего и
адресата, сохранение условий и сокращение повторов черновика без потери сведений.

## Воспроизведение и границы

Ошибки открытия созданного файла в новых сообщениях N1 исправлены и проверены
отдельно: [продолжение разбора](document-open-followup-2026-10-22.md).
Этот результат не меняет указанную выше оценку точности описательного ответа.

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
npm --prefix frontend run build -- --configLoader runner
node tests/local_tools.browser.cjs
.venv\Scripts\python.exe tests/evaluate_agent_documents.py --chat <имя> --spec <приватный-JSON> --reuse-running
.venv\Scripts\python.exe tests/benchmark_evidence_context.py --reuse-running
```

Приватный spec содержит ожидаемые и запрещённые выражения для ответов; он не
передаётся модели. В реальных прогонах используются копии файлов и отдельные
SQLite/Chroma. Исходный чат не переписывается. Полные ответы, действия, проверки,
причины отказов и хеши кода остаются в `.user-evaluation/`.

Первый отдельный сервер перегрузил видеопамять вместе с сервером приложения:
наблюдалось 5893 из 6141 МиБ. Прогон остановлен, его результаты сохранены.
`--reuse-running` использует уже готовые серверы 8081/8082 без их запуска и
остановки; видеопамять вернулась примерно к 3144 МиБ. Новая база и рабочие
файлы при этом остаются изолированными. Изменение не переключает модель приложения.

Чтение исходников, точная замена и конвертация текста не означают произвольную
редактуру оформления или исполнение программ. Поведение небольшой модели при
длинном сложном пересказе остаётся предметом отдельной оценки; положительный
результат файловой операции не является оценкой точности всех текстовых ответов.
