# Локальные документы и репозитории

Инструменты вызываются агентом из обычного чата: поиск точного текста,
структура проекта, создание документа, замена фрагмента и конвертация.
Задачи с кодом выполняет [репозиторный агент](repository-agent.md): он читает и
редактирует исходники, запускает проверки и учитывает их ошибки. Описанные ниже
инструменты документов сохраняют прежние ограничения форматов и источников.
Отдельные формы инструментов убраны из Workspace; там остаются выбор папки,
просмотр файлов и индексация. Выбранная папка остаётся основной
областью работы; библиотека и Google Drive сохраняют свои маршруты и индексы.

## Команды в чате

```text
Покажи структуру проекта
Создай новый документ в этой директории, который опишет наш проект
Мне нужен PDF этого документа, чтобы отправить его коллеге
Сохрани предыдущий ответ отдельной заметкой
Найди текст «archive_code»
Покажи строки 10–30 файла src/lib.rs
Создай файл Заметки.md с текстом «Проверить отчёт перед встречей.»
Открой его
Что ты открыл?
Прочитай созданный тобой документ
Открой Новый документ md
Не то открыл
Создай файл с общим пересказом всего в директории, назови сам
Замени в файле Заметки.md текст «перед встречей» на «до пятницы»
Конвертируй Отчёт.docx в PDF
Конвертируй «Папка/Отчёт.pdf» в «Папка/Извлечённый текст.md»
```

Обычная просьба или однозначная потребность в результате выполняется без второго
подтверждения. Агент выбирает типизированную операцию, использует активный файл
для «этого документа» и выбранную в браузере папку для «здесь». Явно названный
файл приоритетнее. Имя нового документа можно подобрать по теме; занятое
автоматически выбранное имя получает свободный суффикс. Явно заданный путь
не перезаписывается.

## Пересказ всей папки

Просьба создать общий пересказ всей директории распознаётся до модельного
выбора инструмента. Отсутствие имени не требует уточнения: используется
свободное имя «Общий пересказ.md». Явное имя и выбранная/названная папка сохраняются.
Ненайденная явно названная папка не заменяется всем workspace.

Пересказ строится по списку документов, а не по четырём лучшим поисковым
фрагментам. Вложенные папки включаются; действуют исключения индекса. Длинный
текст делится на части без потери конца. Для каждой части автор предлагает
содержательные предложения и выбирает ID дословных доказательств. Отдельная
проверка сравнивает участника, действие и модальность. Неподтверждённый пересказ
не получает подтверждения благодаря одному наличию цитаты.

При замечаниях один раз исправляются спорные предложения и проверяется новый
текст. Принятые предложения не переписываются. Отказ исправления сохраняет уже
проверенную часть. До записи повторно проверяются состав папки и ревизии файлов.
Полный список и результаты сверки доступны в журнале действий чата.

Ограничения обхода, форматов, времени и сверки перечисляются в неполном документе;
ответ получает `PARTIAL`, а не заявление о полном пересказе. Если ни одной
проверенной части нет, файл не создаётся. Охват всех источников означает, что
их части были обработаны, а не что каждая исходная деталь вошла в пересказ.

Это длительная задача: бюджет один раз рассчитывается по объёму, максимум
540 секунд. До 200 исходников и около 1 МиБ текста; превышения показываются
как пропуски. При нехватке контекста часть делится ещё раз. Незавершённый
поток JSON не считается готовым предложением. При большом результате чат
показывает начало с явной пометкой; в файле сохраняется весь текст.

Замечание «это не пересказ, это огрызок» обрабатывается как исправление
предыдущего действия. Исходная задача восстанавливается из журнала, а не
заменяется чтением результата. Для сохранённого неполного пересказа после
перезапуска backend переиспользуются неизменённые проверенные разделы.
В незавершённом файле также сохраняются принятые предложения с действующими
цитатами; исправлению передаются предыдущие замечания. Повтор уже принятого
предложения не считается восстановлением отвергнутой части.
Новая версия получает свободное имя; предыдущая остаётся доступной. Собственные
результаты этой цепочки исключаются из источников. Для уже полного пересказа
такое замечание увеличивает подробность вместо дословного повторения.

Имена без точки перед распространённым расширением разрешаются буквально.
«Не то открыл» обращается к журналу: однозначный исходный буквальный файл
может быть открыт заново; при отсутствии такого имени запрашивается только
нужный путь. Замечание не становится фактическим вопросом к документам.

Результаты и границы проверки: [разбор нового N1](practical-chat-gaps-2026-10-23.md).

После сохранения результат становится активным файлом, а его папка — текущей.
«Открой его» и «прочитай его» выполняются по этому пути без модели.
«Созданный тобой документ» находит последнее действительно сохранённое создание
или конвертацию в журнале того же чата и workspace, даже после чтения другого файла
или сокращения истории. Учитывается и сохранение после отдельного «да»;
неприменённый предпросмотр и правка другого файла не заменяют этот результат.
«Что ты открыл?» сообщает последнее успешное открытие из журнала без повторного
чтения или открытия. Для буквального имени с расширением нужны точное совпадение
или выбор пользователя; похожий файл автоматически не подставляется.
Неявная текущая папка не скрывает точное имя в другом месте workspace;
явно запрошенная папка остаётся ограничением поиска.

Если готового текста нет, навык ищет сведения в текущем workspace, составляет
содержимое, редактирует и независимо проверяет его. Старые ответы чата не
являются доказательствами. В описание лица не передаются предложенные
примеры от первого лица для проговаривания; исходники всё равно доступны проверке.
Такая же подготовка применяется к короткому вопросу «Кто такой …?» в чате.
Явный запрос разбора примеров сохраняет их контекст. При неполной сверке можно
сохранить только целые уже подтверждённые предложения с действительными
источниками; без подтверждённого содержимого файл не создаётся. Просьба сохранить
предыдущий ответ копирует его целиком и не означает новой проверки фактов.

Для предварительного просмотра напишите «Предпросмотр: …» или «не сохраняй».
Тогда «да» применяет изменение, «отмена» оставляет файлы прежними. Неизвестный
файл или тему можно сообщить следующим ходом; при смене workspace ожидающее
действие не переносится.

Модель разрешает параметры через каталог, а категория действия допускается
только исходными словами пользователя. Фрагменты точной замены old/new должны
буквально присутствовать в просьбе. Вопрос о содержимом, отрицание, объяснение
«как сделать» и цитируемая команда не разрешают запись. Команды источников не исполняются.
Пути и текст могут быть в «ёлочках», обычных двойных кавычках или backticks.

## Поддержка и ограничения

- Поиск — буквальный, без учёта регистра, с относительным путём и номером строки.
  Для PDF/DOCX/HTML строки относятся к извлечённому тексту. Это дополнение к
  обычному смысловому поиску. Полные буквальные просьбы выполняются без модели;
  для косвенной формулировки возможен структурированный выбор операции.
- Обход для индекса и поиска учитывает вложенные `.gitignore`, включая отрицания,
  и прежние встроенные исключения. Глобальные Git-настройки не читаются. Правила
  влияют на обнаружение; явно запрошенный допустимый файл можно прочитать отдельно.
  Недоступные правила дают ошибку охвата, не снимают исключения молча.
- Читаются прежние документы и исходники, а также Rust, Go, Java/Kotlin, C/C++, C#,
  Ruby, PHP, Swift, Vue/Svelte/Astro, MJS/CJS, RST/TEX, GraphQL/Proto и другие
  перечисленные в `workspace_document_reader.py` форматы. README, LICENSE,
  Dockerfile, Makefile и файлы правил читаются и без расширения. Код не запускается.
- Точная замена доступна для TXT, MD/Markdown, CSV и TSV. По умолчанию нужен ровно
  один совпадающий фрагмент; API позволяет указать ожидаемое число до 100.
  Сохраняются исходные UTF-8/BOM/CP1251 и окончания строк. Для DOCX/PDF сначала
  можно получить текстовую копию; редактирование оформления пока не реализовано.
- Создание и экспорт: TXT, MD/Markdown, CSV, TSV, HTML, DOCX и PDF. CSV/TSV
  сохраняют извлечённый текст без восстановления таблицы. Конвертация переносит
  текст, без оформления и изображений. HTML экранируется, внешние ресурсы не
  загружаются. PDF использует установленный PyMuPDF, без LibreOffice/облачного API.
- Новая копия никогда не перезаписывает существующий файл. Родительская папка
  должна существовать. Запись ограничена относительными путями workspace;
  скрытые/служебные каталоги, секреты, скрипты, symlinks/junction и NTFS streams
  не допускаются как цели записи. Прежняя политика чтения сохраняется.
- Перед заменой проверяется хеш исходных байтов и сохраняется копия в
  `.fortuna-backups/`. Запись публикуется через временный файл в том же каталоге;
  создание использует атомарную операцию без перезаписи. Файл проверяется снова
  перед заменой. Блокировка сериализует записи одного backend; сторонний редактор
  не участвует в этой блокировке. Копии сохраняются на диске без автоматической
  очистки; восстановление пока выполняется пользователем из резервной копии.

Предпросмотр живёт 10 минут, до 24 предложений и 32 МиБ на backend. Перезапуск
сбрасывает предложения. Исходный/редактируемый текст ограничен 1 МиБ, результат —
20 МиБ, PDF — 100 страниц/15 секунд между страницами. Просмотр диапазона — до
500 строк/32 000 символов. Поиск — до 2000 читаемых файлов и 100 результатов
(по умолчанию 50). Ограничения и ошибки охвата передаются явно.

## Контракты

`LocalToolsSkill` зарегистрирован как `local_tools`: `repository_overview`,
`search_text`, `read_lines`, `create_document`, `edit_document`,
`convert_document`, `execute`. `local_tool_intent.py` разрешает цель и параметры,
а навык связывает поиск, составление и файловые операции. Запись проходит
подготовку точных байтов и проверяемый apply внутри навыка. Произвольный apply
недоступен LLM-планировщику. Журнал хранит `RESOLVE_LOCAL_TOOL`, `PLAN_DOCUMENT`,
действия чтения/сверки и `APPLY_DOCUMENT_CHANGE`.

Все HTTP-маршруты защищены обычными Host/Origin/токеном приложения:

| Метод | Путь после `/workspaces/{id}` | Назначение |
| --- | --- | --- |
| GET | `/repository` | Типы файлов и ограниченная структура |
| GET | `/search?query=...&directory=...&max_results=50` | Точный поиск |
| GET | `/lines?path=...&start=1&end=200` | Диапазон строк |
| POST | `/documents/preview` | `operation=create/edit/convert`, параметры документа |
| POST | `/documents/apply` | Сохранение по `proposal_id` в том же workspace |

Модули: `workspace_repository_tools.py`, `workspace_documents.py`,
`local_tool_intent.py`, `local_tools_skill.py`, `local_tools_routes.py`,
`assistant_core.py`, `frontend/src/App.tsx`.
Добавлена зависимость `pathspec==1.1.1`; другие конвертеры не требуются.

## Проверки

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -p test_local_tools.py -v
.venv\Scripts\python.exe -m unittest discover -s tests -p test_agent_documents.py -v
.venv\Scripts\python.exe -m unittest discover -s tests -p test_created_document_followup.py -v
.venv\Scripts\python.exe -m unittest discover -s tests -p test_compact_evidence.py -v
npm --prefix frontend run build -- --configLoader runner
node tests/local_tools.browser.cjs
```

Браузерному тесту нужен установленный Playwright (`PLAYWRIGHT_MODULE_PATH` может
задавать путь к пакету) и Edge. Он поднимает настоящий изолированный backend,
SQLite и файлы в `.user-evaluation/`, использует production UI и не запускает
модели. Проверяет поиск, резервную копию, применение/отмену, кириллицу в PDF,
HTTP-авторизацию, устаревшую правку и границу путей.
Также проходит создание → открытие по местоимению/имени → отчёт о действии →
чтение другого файла → открытие ранее созданного. Системный opener заменён
регистрацией пути, поэтому тест не запускает приложения Windows.

`evaluate_document_followup.py --chat <имя>` повторяет файловые запросы из
существующего чата с его реальными файлами и журналом создания в изолированной
копии. Рабочая SQLite открывается только для чтения. Вызовы модели запрещены,
открытия перехватываются; проверяются пути, отсутствие чтения/записи и хеши
исходников, базы и выбора модели. Это проверка маршрутизации действий,
не оценка качества пересказа или времени запуска системного приложения.

`evaluate_agent_documents.py --chat <имя> --spec <приватный JSON> --reuse-running`
воспроизводит вопросы выбранного чата и настоящие файловые операции в копии
источников с отдельными SQLite/Chroma. `--reuse-running` использует готовые
локальные серверы 8081/8082 без запуска и остановки, чтобы не загружать вторую
GGUF в занятую видеопамять. Без флага запускаются собственные серверы.
Рабочая база, выбор модели и источники проверяются по хешам; приватные ответы
остаются в `.user-evaluation/`.

`tests/evaluate_local_workspace.py --workspace <папка> --cases <приватный JSON>`
запускает GGUF из dev-конфигурации (по умолчанию `chat.gguf`, либо
`EVALUATION_MODEL_PATH`) в отдельном сервере и
проверяет ответы по существующим документам без их изменения. Схема случаев
описана в файле скрипта; допустимы `required_any`, `required_evidence`,
`missing_fact`. Тексты вопросов, ответы и цитаты остаются в игнорируемом выводе.
Фактические результаты этой сессии: [local-assistant-results-2026-10-22.md](local-assistant-results-2026-10-22.md).
