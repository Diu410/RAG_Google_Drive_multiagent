# Развитие Фортуны в персонального агента

Цель — выполнять задачи в выбранной папке по обычной просьбе: использовать
инструменты, учитывать их результат, проверять изменения и сохранять опыт.
Документы, источники и Google Drive остаются частью системы.

Ориентиры: у [OpenCode](https://opencode.ai/docs/tools/) есть инструменты чтения,
поиска, правки, запуска команд и диагностики; [режимы агентов](https://opencode.ai/docs/agents/)
разделяют анализ и выполнение. [Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/tools)
объединяет инструменты, память и задачи; его [навыки](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)
загружаются по необходимости. Это функциональные ориентиры, а не заявление
о совместимости или равном качестве моделей.

## Этап 1: выполнение задачи с обратной связью

Реализуется в этой итерации:

- Обычная просьба в чате включает агентский цикл для репозитория до старого
  маршрутизатора документов и планировщика. Анализ не разрешает запись.
- Агент получает структуру, доступные проверки, правила проекта и каталог навыков.
  Каждый следующий инструмент выбирается после настоящего результата предыдущего.
- Чтение, буквальный поиск, точная правка, полная замена небольшого прочитанного
  файла и создание исходника. Существующие файлы сохраняют резервные копии;
  внешняя правка вызывает отказ по версии.
- Python unittest/pytest и существующие npm test/build/lint/typecheck.
  Инструмент принимает ID обнаруженной проверки, а не произвольную команду модели.
  Падение, код выхода, вывод, таймаут и отмена возвращаются в цикл и журнал.
- Проверка до последней правки не подтверждает новую версию. Пустой набор тестов,
  преждевременный finish и неисполненные обещания модели не дают успешного итога.
- В интерфейсе видны реальные действия, diff и вывод проверок, включая после
  перезагрузки чата. Неполная задача сохраняет изменения и фактический результат.
- Реальные повторы на неизменных копиях Python/JavaScript-проектов. Критерии
  поведения находятся вне доступных агенту папок; тесты и конфигурация сравниваются
  по хешам. Маленькая модель оценивается отдельно от контролируемого исполнителя.

## Этап 2: память и повторное использование

Следующая самостоятельная итерация:

1. Память проекта с происхождением, временем и областью действия. Предпочтения
   пользователя отделяются от утверждений источников и результатов инструментов.
2. Каталог пользовательских SKILL.md с чтением по запросу/задаче, версией,
   источником и возможностью отключения. Успешная проверенная процедура может
   стать предлагаемым навыком; неудачный запуск не превращается в рецепт успеха.
3. Возобновление прерванной задачи из журнала: перепроверка файлов и среды,
   повторное чтение изменённого контекста, отсутствие повторной записи того же эффекта.
4. Общий цикл для документов: найти несколько источников, составить документ,
   проверить, сохранить и конвертировать в рамках одной задачи.

## Этап 3: разработка и внешние инструменты

1. Git status/diff с фильтрацией секретов и без внешних diff-драйверов; работа
   с отдельной веткой/worktree и просмотром изменений перед публикацией.
2. Диагностика языковых серверов и точный поиск определений/ссылок.
3. Управляемые терминальные процессы с полноценным владением деревом процессов,
   потоковым выводом и изолированной средой. Текущие локальные проверки не
   являются песочницей ОС и исполняют код проекта с правами пользователя.
4. Подключение MCP и инструментов веба/браузера в общий каталог с сохранением
   источника результата и полномочий исходного запроса. Google Drive сохраняется.
5. Планирование локальных задач по времени с журналом, отменой и ограничением
   повторов. Отправка сообщений вовне требует отдельного поручения пользователя.

## Как оценивать прогресс

Успех — выполненная задача и проверяемый эффект, а не правильное имя инструмента
или убедительный финальный текст. Храним отдельно долю завершённых задач,
качество результата, число лишних действий, время до первого полезного действия,
полное время, вызовы/токены модели, отказы и сохранность пользовательских данных.
Плохие прогоны сохраняются; критерии не ослабляются после результата.

Ближайшая цель после этой итерации — устойчивые многофайловые задачи и продолжение
работы после перезапуска. Массовое добавление инструментов до стабильного
исполнения затруднит выбор небольшой локальной модели.
