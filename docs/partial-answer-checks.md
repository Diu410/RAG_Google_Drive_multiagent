# Сохранение ответа при остановке проверки по времени

Описание ниже относится к `ANSWER_REVIEW_MODE=strict`. В обычном чате действует
[контекстная сверка](contextual-answer-review.md): технический отказ сохраняет
полное объяснение с незавершённым статусом.

В разобранном прямом вопросе об адресате система потратила около 37 секунд
до генерации и ещё 67 на черновик. На проверку осталось 15 секунд из общего
FAST-бюджета 120. Технический отказ потерял конкретную причину и показал
«проверка временно недоступна». Готового независимого подтверждения черновика
в журнале не было; хорошая структура сама по себе его не подтверждает.

## Маршрут и бюджет

«Какие параметры сборки указаны в отчёте?», «С кем работает подрядчик?» и «Для кого готовят отчёт?»
распознаются как прямые информационные вопросы. Они не запускают workflow planner.
В выбранной папке область workspace определяется правилом без модельного
маршрутизатора. Запрос библиотеки, явно распознанная беседа, операции с файлами
и последовательности действий сохраняют прежние маршруты. Короткий
информационный вопрос получает `NORMAL` без модельного выбора подробности;
явная просьба анализа и краткости имеют приоритет. Извлечение источников остаётся.
Общие инструкции генерации описывают относимость, атрибуцию, направление связей
и модальность. В них нет обязательного описания персонажей, организаций или
доктрин для любого вопроса; эти темы не определяют поведение системы.

## Проверка без переписывания цитат

`verification_ids.py` применяется только при `supports_evidence_ids is True`.
Сервер назначает ID исходным предложениям ответа и дословным предложениям
найденных источников. Проверяющий возвращает тип предложения, статус, основу,
относимость и ID цитат для каждого предложения. Несколько фрагментов могут
совместно подтверждать одно предложение, в том числе из разных документов.
Отсутствующее предложение, неизвестный ID,
незавершённый JSON и неполная оценка не принимаются. Заголовки и ссылки
на известные исходные файлы не считаются утверждениями о предмете вопроса.

Текст и цитату восстанавливает сервер. Модель не может незаметно подменить
проверяемую фразу своим пересказом. Составное предложение подтверждается
целиком: цитата, доказывающая только его часть, не достаточна. Указание на
отсутствие сведений внутри положительного утверждения не отключает его аудит.
Обязательное поле `contains_positive_facts` различает чистое сообщение о
недостатке сведений и предложение, содержащее хотя бы один положительный факт.
Например, «Версия не указана, но сборка занимает 80 минут» всё равно требует
проверки длительности. Ошибочная метка `UNANSWERED` не скрывает этот факт.
Это общий контракт проверки предложений; имена, темы документов и особые
маршруты вопросов о персонажах в нём не предусмотрены. Классификация выполняется
моделью и также может ошибаться; наличие поля само по себе не гарантирует точность.
Положительные факты независимо проходят прежний смысловой аудит: субъект,
действие с объектом, модальность, говорящий/адресат, пример и относимость.
Совпадающая цитата из другого документа не меняет выбранный источник.
Провайдеры без этой возможности сохраняют прежний контракт проверки.

## Незавершённая проверка

`GenerationDeadlineExceeded` даёт явную причину «по лимиту времени».
Общая проверка остаётся `UNAVAILABLE`, если проверены не все части или
не завершён смысловой аудит. Готовые независимые оценки предыдущих частей
и фактов сохраняются; ожидающие аудита утверждения получают `UNAVAILABLE`,
а не `SUPPORTED` или ложное `UNSUPPORTED`. Частичный JSON не используется.
Если технически прервалось исправление или повторная проверка нового пересказа,
сохраняются оценки исходного ответа и причина отказа. Новый текст не получает
старое подтверждение; отбор использует исходные неизменённые предложения.

Workspace отбирает целые неизменённые проверенные предложения, относящиеся
к вопросу, и проверенные сообщения о недостатке сведений. Цитата повторно
сопоставляется с исходным документом; предложение с потерянным местоименным
субъектом не переносится. Показанный сокращённый текст получает собственную
оценку только по включённым фразам, а предупреждение сохраняет причину
остановки. Содержательная подтверждённая часть может остаться ответом.
У короткой сохранённой фразы может быть показана одна дословная цитата из
выбранного источника. У неё отдельное подтверждение только совпадения с текстом;
она не подтверждает трактовку и не доказывает отсутствие сведений во всей папке.
Если подходящих оценённых предложений нет, показывается технический отказ.
Новая генерация и восстановление после этого не запускаются.

Бюджеты 120/180/240 секунд не увеличены. Это не гарантия одинаковой скорости
на любом оборудовании или безошибочности модельного аудитора. Незавершённая
проверка не доказывает, что нужных сведений нет во всей папке.

В реальном повторе 9B генератор предложил связь, которая не следует из текста,
а смысловой аудитор ошибочно её подтвердил. Остановка по времени и сохранение
оценок исправляют работу цепочки, но не устраняют эту ошибку модельной оценки.
Качество ответов о связях ещё требует улучшения; тесты механизма не являются
доказательством достоверности всех реальных ответов. Тематические исключения
для исправления этого примера не добавлены.

## Проверки

`tests/test_partial_answer_verification.py` проверяет полный путь workspace:
сохранение неизменённых фраз и причины остановки без новой генерации,
разрешение доказательств по ID, отказ отсутствующих ID/предложений,
независимый аудит, сохранение завершённых оценок, отказ зависимых местоимений,
подменённой цитаты и нового пересказа. Отдельные сценарии используют параметры
сборки и направленные связи между сервисами; отсутствие версии не скрывает
неверную длительность, перестановка участников связи не наследует подтверждение.
Проверки маршрутизации и обычного
бюджета дополнены в `tests/test_rag_optimizations.py`.

Финальный общий прогон: 424 теста за 49,8 секунды, все прошли. Отдельно проверены
как исключение при исправлении, так и возвращённый `UNAVAILABLE` при повторной
проверке: оба пути сохраняют исходные оценки и конкретную причину остановки.
Этот результат относится к механике цепочки; найденная в повторе 9B ошибка
смыслового подтверждения связи остаётся открытой.

Рабочая история прочитана через SQLite `mode=ro`. Снимки, журнал и результаты
повтора находятся в игнорируемой `.user-evaluation/recipient-review-2026-10-10/`.
Повтор использует сохранённый пакет источников, отдельную временную базу и
собственный сервер 9B; время запуска отделено от времени ответа.
