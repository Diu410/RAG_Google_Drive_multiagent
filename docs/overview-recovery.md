# Проверка и восстановление обзорного ответа

Для коротких обзоров workspace со структурированным провайдером теперь применяется
[предварительная подготовка проверенных сведений](fact-first-overviews.md).
Описанные ниже правила доказательств сохраняются; повторная цепочка свободного
синтеза для этого пути заменена одной попыткой пересказа проверенных сведений.

Изменения следуют из [сравнительных повторов 4B/9B](model-comparison.md).
Они устраняют зависимость буквального сообщения о тексте от модельного выбора
доказательств и потерю уже подтверждённых сведений при восстановлении ответа.

`Verifier` сопоставляет буквальные сообщения исходного ответа с доступными
фактическими текстами источников до генерации оценки. Проверяет оставшиеся
предложения отдельно и объединяет оценки без изменения исходных предложений.
Наличие цитаты подтверждает только то, что она присутствует в тексте;
соседняя трактовка, биография или новое правило всё ещё требуют проверки.
При техническом отказе оставшейся проверки итог не получает успешный статус.

Дополнительно проверяются два узких сообщения о структуре текста. Дословное
требование в рамке «В тексте сказано, что …» принимается только при совпадении
всей исходной фразы, включая модальность; допустимо прямое подтверждение
«Ты был прав, когда сказал, что …». Отрицание этого подтверждения не подходит.
Сообщение об использовании названия в примере требует дословного «Например — Я…»
и присутствия всех тематических слов названия в самой цитате. Эти правила
подтверждают текстовый контекст, а не истинность убеждения или реальную личность.

`EvidenceAuditor` различает сообщение о документе и утверждение о реальном мире
в инструкциях смыслового аудита. Защита адресата применяется к лицам, включая
названных персонажей, а не к документам. Наличие случайного обращения внутри
самоописания говорящего также не превращает его в адресата. Отказ по адресату,
говорящему или усилению модальности сохраняет причину в журнале.

`OverviewSynthesizer` может объяснить использование названия в примере, если
сохранён окружающий контекст. Голый пример остаётся цитатой. Генерируемое
объяснение не получает подтверждение автоматически и проходит обычный аудит.

Восстановление сохраняет неизменённые подтверждённые относящиеся к вопросу
предложения предыдущего ответа вместе с проверенными предложениями кандидата.
Каждое должно иметь действительную цитату и совпадать с исходным предложением.
Утверждения с неразрешёнными местоимениями не переносятся отдельно. Итоговая
панель пересчитывается по показанному тексту; новый пересказ не наследует оценку.

## Проверки

Offline-набор: **293/293**, успешно. Включает восстановление действительного
источника цитаты до модели, защиту документального описания от постороннего
обращения, сохранение отказа при ложном именовании адресата, сохранение полезного
факта при восстановлении, запрет подтверждения нового пересказа, сохранение
модальности требования и запрет превращения примера в биографию.
Дополнительная проверка всей `WorkspaceSkill` подтверждает сохранение полезного
факта после принятия документального восстановления. Пример должен находиться
целиком в одном источнике: соединение фрагментов разных файлов не доказывает
заявленное использование названия в примере.
Frontend и desktop в этой задаче не изменяются.

## Повтор на установленных моделях

По одному полному повтору исходного короткого обзорного вопроса с тем же
замороженным пакетом источников дали следующий результат:

| Модель | Проверенный итог | Панель совпадает с ответом |
| --- | --- | --- |
| Qwen 3.5 4B Q4_K_M | `SUPPORTED / EXPLANATORY`, два относящихся к вопросу текстовых факта | Да |
| Qwen 3.5 9B Q4_K_M | `SUPPORTED / EXPLANATORY`, те же два факта | Да |

Сохраняются использование названия в явно обозначенном примере высказывания
о себе и дословное требование к роли. Общая фраза из соседнего абзаца не
становится определением названной группы. Это обзор того, что сообщают тексты,
а не доказательство реального существования организации или полной доктрины.

После ограничения примера одним непрерывным фрагментом одного источника
итоговые факты обеих моделей повторно проверены текущим кодом без модельного
вердикта; итоговая панель пересчитана по неизменённым предложениям.
Дополнительная защита сохранения факта при успешном объяснительном восстановлении
проверена тестом всей цепочки. Промежуточный аппаратный прогон до добавления
структурных правил остановлен и исключён из итоговой оценки.

Свободный вручную составленный пересказ 4B по-прежнему проверяет лишь частично:
название и требование подтверждены, описание приёма в свободной формулировке
отвергнуто. Исправление не устраняет все ложные отрицательные решения локальной
модели; оно делает восстановление исходного вопроса независимым от такой оценки
для доказуемых сообщений о тексте.
9B подтвердила все три факта этого контрольного пересказа (`SUPPORTED`), но
самоназвание ошибочно пометила как постороннее. Поэтому статус проверки фактов
и полнота пригодного для обзора результата по-прежнему различаются.

Обе модели отклонили исходное выдуманное утверждение об учителях и правилах
группы (`UNSUPPORTED`). Все шесть реальных случаев завершились без технических
ошибок. Запущенные оценкой серверы остановлены; SHA-256 рабочей базы и файла
сохранённого выбора модели совпали до и после серии. Сырые результаты и личные
источники остаются в игнорируемой `.user-evaluation/`. `git diff --check` и
проверка ссылок обновлённой документации прошли.

Реальный поиск, HTTP и desktop UI этим повтором не измерены. История читается
read-only, записи цепочки идут во временную базу. У оценочных серверов частичная
выгрузка восьми слоёв на GPU; их время не является оценкой штатной скорости.
