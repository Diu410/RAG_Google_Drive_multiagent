# План развития локальной «Фортуны»

Цель сессии от 22 октября 2026: ускорять полезный ответ, сохранять проверку
смысла и точность по источникам, подготовить помощника к локальным репозиториям,
добавить чтение, редактирование и конвертацию документов. Google Drive остаётся.
Работа ведётся в текущем репозитории с сохранением существующих изменений.

Этапы 1–6 реализованы и проверены. Замеры, обнаруженные отказы и границы
завершённого этапа: [local-assistant-results-2026-10-22.md](local-assistant-results-2026-10-22.md).
Раздел «Следующие итерации» содержит дальнейшие направления, а не обещание
уже выполненных изменений.

## Порядок и критерии

1. **Исходные измерения.** Полный offline-набор и реальные GGUF-прогоны с обычной
   редактурой BALANCED: известный факт, два параметра, внедрение инструкций,
   отсутствующий факт. Базы/модель пользователя не изменяются; отдельные серверы,
   SQLite и Chroma, прогрев отдельно. Сохранять времена действий, вызовы и токены.
2. **Стоимость проверки.** Испытать компактный транспорт независимого аудита:
   все сравнения субъекта, предиката, модальности и относимости обязательны.
   Внутренние оценки и журнал сохраняют прежние полные поля. Пропущенное поле,
   обрыв, дублирование ID и невалидная оценка не дают подтверждения. Сравнить
   одинаковые запросы до/после; сохранять ускорение только при успешных проверках.
3. **Локальные репозитории.** Расширить чтение распространённых исходников,
   поддержать исключения .gitignore, ограниченный поиск с номерами строк и обзор
   дерева/типов файлов. Без запуска кода, Git hooks, внешних команд проекта и
   доступа к секретам. Результат поиска содержит область и признак ограничения.
4. **Документы.** Новый зарегистрированный навык и HTTP API: чтение диапазона
   строк, создание текстового документа, точная замена фрагмента, конвертация
   извлечённого текста в TXT/Markdown/HTML/DOCX/PDF. Изменение исходника — через
   конкретный diff, контроль ревизии и резервную копию; конвертация — в новый
   файл без перезаписи. Различать извлечение текста и сохранение оформления.
5. **Доступность инструментов.** Добавить операции в каталог навыков, чат и UI
   выбранной папки. Намерение брать из исходной реплики пользователя; инструкции
   источника и выдуманные моделью параметры не разрешают запись. Смена workspace
   не переносит подготовленные изменения. Отказы объясняются пользователю.
6. **Итоговая проверка.** Регрессии границ путей, симлинков/junction, секретов,
   устаревшего предпросмотра, конкурирующих записей, отмены и свежести источников;
   сборка UI; реальные прогоны документов и ответов. Обновить AGENTS/README и
   сохранить отчёт с фактическими измерениями и ограничениями.

## Следующие итерации по результатам

- Расширять набор качества: отрицание, условие, противоречащие документы,
  длинный документ с фактом в конце, русские имена, смешанный известный/неизвестный
  факт, неверное направление отношения. Проверять каждое условие отдельно.
- Сравнить FAST/BALANCED/REASONING и установленные GGUF при одинаковых источниках,
  числе повторов и редактуре. Не менять выбранную пользователем модель без
  убедительного преимущества по качеству и задержке. Два повтора — разведка,
  для p95 нужны десятки повторов и стабильная нагрузка.
- Ускорять поиск и упаковку только по профилю: инкрементальный индекс, точный
  лексический поиск исходников, кэш по ревизии; проверка всех выбранных источников
  остаётся. Отдельно измерять холодный старт и запрос к прогретой модели.
- После устойчивого текстового контура: адресное редактирование DOCX с сохранением
  оформления, таблицы XLSX, OCR по запросу, пакетная конвертация с отчётом,
  локальные пользовательские рецепты. Новые операции получают отдельные контракты
  и границы; обещания поддержки не заменяют реализованные инструменты.

## Правила принятия решений

Ускорение не принимается ценой ложного SUPPORTED или потери фактов. Неполный
поиск не доказывает отсутствие сведений. Содержимое документов не является
инструкцией на изменение файлов. История, Drive, рабочие базы и GGUF сохраняются.
Приватные артефакты остаются в игнорируемой `.user-evaluation/`; в документацию
попадают только синтетические примеры и агрегированные результаты. Итог выполнения
и незакрытые ограничения фиксируются отдельным отчётом этой сессии.
