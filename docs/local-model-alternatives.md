# Локальные модели: скорость и ошибки интерпретации

Проверка начата 10 октября и продолжена 11 октября 2026 года. История чата и
журнал задач прочитаны через SQLite `mode=ro`. Повторы используют сохранённый
пакет из четырёх найденных фрагментов и временные базы, не редактируют историю
пользователя и не вызывают новый поиск. Источники и вопросы не передавались
внешним моделям. Частные запросы, ответы, журналы и сценарии повторов находятся
в `.user-evaluation/model-alternatives-2026-10-10/` и исключены из Git.

## Оборудование и методика

Intel i5-12500H, 15.71 ГиБ доступной системе физической RAM, RTX 4050 Laptop
с 6141 МиБ VRAM, драйвер 537.53. Установленный llama.cpp: b11060, commit
`426090367`, CUDA 12.4. Контекст — 4096 токенов, 6 CPU-потоков, batch — 256,
один параллельный слот. Запускается только собственный сервер на 127.0.0.1:8097;
после каждого опыта он останавливается. Серверы пользователя не завершаются.
Embeddings в этих опытах не запущены; конфигурация проекта размещает их на CPU.

Для скорости после прогрева выполнены два запроса `/completion`, каждый
генерирует ровно 128 токенов при `temperature=0`, отключённом prompt cache и
`ignore_eos=true`. Во всех опытах одинаковый русский текст о двух сервисах и
условном выпуске версии. У Qwen 3.5 он занимает 591 токен, у Gemma — 605,
у Qwen3 Instruct — 763: скорость
в токенах нельзя считать точным коэффициентом ускорения между токенизаторами.
Время полной цепочки дополнительно измеряется по одному и тому же вопросу и
неизменному пакету источников; оно не включает загрузку сервера и прогрев.

Исходный резерв автоматического размещения — 1024 МиБ. Его уменьшение позволяет
держать больше весов на GPU. Эти замеры показывают изменение скорости, а не
гарантируют запас памяти при запуске других GPU-приложений. Параметры приложения
не заменены на агрессивный вариант; лимиты времени ответов не увеличены.

## Что показала последняя переписка

В свежем журнале один ответ завершился за 71.42 секунды, другой оборвался на
120.11 секунды. По последовательности загруженных весов в серверном журнале и
времени отдельных генераций первый соответствует 4B, второй — 9B. Сохранённый
сейчас выбор 9B не доказывает, что предыдущий запрос также выполняла 9B.
Задача не записывает физические веса каждого вызова, поэтому сопоставление
сделано по серверному журналу, а не по самому полю FAST.

Основная ошибка — перенос роли говорящего на неназванного адресата письма.
Исправляющий этап также добавлял неподтверждённые отношения. Аудитор иногда
принимал их при положительных `same_subject`/`same_predicate`/`same_modality`.
Правильное происхождение цитаты не доказывает правильность такого прочтения.
Поиск уже находил нужное письмо; смена retrieval не исправляет эти ошибки.

На замороженном пакете 4B до изменения управления JSON завершила ответ за
78.99 секунды и выдала ошибочную идентификацию адресата. 9B с резервом 512 МиБ
и KV q8_0 дошла до общего лимита 120.10 секунды. 9B с исходными параметрами
после изменения управления JSON также дошла до 120.11 секунды. Ускорение
декодирования не гарантирует, что проверка, исправление и повторная проверка
закончатся в срок.
4B с новым управлением JSON также завершила повтор за 78.79 секунды, сохранив
ошибочную связь между говорящим и адресатом. Уменьшение batch с 256 до 64
практически не изменило скорость декодирования 9B, но замедлило обработку входа;
такое изменение не принято.

## Скрытое рассуждение вместо JSON

Gemma при `enable_thinking=false` расходовала весь бюджет сложного аудита на
`reasoning_content`, оставляя `content` пустым. Даже нулевой бюджет вместе с
этим выключенным шаблоном в отдельном повторе закончился после 1000 токенов
без JSON. Такой ответ правильно отклоняется как незавершённый.

Повтор того же аудита с доступными серверу разделителями рассуждения и жёстким
нулевым бюджетом вернул валидный JSON из двух оценок: 389 токенов, 13.77 секунды,
`finish_reason=stop`, скрытых рассуждений нет. Поэтому структурированные вызовы
с выключенным размышлением теперь используют reasoning-capable шаблон и
`reasoning_budget_tokens=0`. Обычная текстовая генерация сохраняет выключенный
шаблон: принудительное закрытие включённого шаблона без JSON-грамматики в одном
отдельном опыте вывело последующий анализ в текст. Этот вариант отвергнут.
Регрессионная проверка защищает и возврат JSON, и обычный текст.

С исправленным управлением JSON полный повтор Gemma занял 45.89 секунды,
проверки больше не обрывались. Но итог остался слабым: модель дала косвенную
интерпретацию вместо определения адресата, а проверка сохранила только одну
фразу о совпадении целей. Это подтверждает пригодность по скорости и
совместимость с текущей цепочкой, но не превосходство по качеству.

## Общие задачи чтения

В отдельной серии используются восемь синтетических вопросов: говорящий и
адресат, подпись, пример без биографического значения, направление зависимости,
условный выпуск, известный порт, отсутствующая версия, автор и персонаж.
Схема требует `true` для выводимого утверждения, `false` для противоречащего и
`null` для неизвестного; объяснение сохраняется отдельно. Это проверка чтения
малого набора, не оценка общего интеллекта и не автоматическая оценка качества
пользовательского ответа.

4B с исходным и новым управлением JSON дала 6/8 точных значений: ошибочно перенесла
роль на адресата и приняла учебный пример за роль автора. 9B Q4 с исходными
параметрами и новым управлением JSON — 7/8: вместо отсутствующей версии
вернула отрицание. Gemma с новым управлением JSON — 7/8: отрицание вместо
`null` у учебного примера, при этом объяснение верно различало пример и
биографию. Эти ошибки имеют разный смысл; одинаковый балл не означает одинаковое
качество. Ускоренная 9B Q4 с KV q8_0 до изменения управления JSON дала 8/8.

## Установленные альтернативы

Выбор весов отделён от FAST/BALANCED/REASONING. Добавлены ID `qwen9b-q3` и
`gemma4e4b`; каждый требует собственного файла в `DATA_DIR/models`. Переключение
сохраняет бюджеты режимов, изменяет только веса chat-сервера и не переиндексирует
документы. Активные embeddings сохраняются. Отсутствующие файлы отключены в меню.
Эти два варианта доступны для сравнения; результат проверки не позволяет
рекомендовать их как исправление качества ответов.

Q3_K_M уменьшает размер Qwen 9B с 5.63 до 4.67 ГБ. Это снижение точности весов
той же модели; оно требует проверки качества, а не обещает его сохранение.
При исходном размещении полный повтор также дошёл до 120.08 секунды. Восемь
малых задач дали 6/8: модель ошибочно вывела отсутствие роли из подписи другого
участника и приняла неизвестную версию за противоречие. С резервом 512 МиБ и
KV q8_0 загрузка подтвердила 33/33 слоёв на GPU, скорость выросла до 32–33 токенов/с.
Полная цепочка в таком размещении завершилась за 76.92 секунды, но сохранила
только буквальную цитату с предупреждением об ограниченности ответа. Ошибки
в двух малых задачах также остались. Оснований считать Q3 равной Q4 по качеству
или рекомендовать её как улучшение интерпретации этот опыт не дал.
Выбор Q3 в меню сам по себе не включает уменьшенный резерв, Flash Attention
или квантование KV. Замер 76.92 секунды относится к отдельному серверу с
`--fit-target 512 --flash-attn on --cache-type-k q8_0 --cache-type-v q8_0`.
При обычном запуске приложения остаются исходные параметры и результат
120.08 секунды. Настройки рабочего сервера автоматически не изменялись.
Проверяемый файл: [Unsloth Qwen3.5-9B](https://huggingface.co/unsloth/Qwen3.5-9B-GGUF/tree/3885219b6810b007914f3a7950a8d1b469d598a5),
SHA-256 `8fed90306e4f019e2bf35f3766470b7bc59ea1a9dae00f5ceb20b43cb5514393`.

Gemma E4B — 5.15 ГБ для текста: [официальный Google GGUF](https://huggingface.co/google/gemma-4-E4B-it-qat-q4_0-gguf/tree/4b4a2c1d584be7264f87aac328a1bc739ce81b6c),
SHA-256 `676c35070db6dbe52f93e9c864ee0fba4eddea94b9c875d9cb10daff453fbaee`.
Обозначение E4B относится к эффективным параметрам, а не общему объёму весов.
Мультимодальный projector не загружен, для текста он не нужен.

[Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)
также проверена локально: 54.50–54.60 токенов/с, 7/8 малых задач и 77.18 секунды
на полный повтор. Она перевернула направление вопроса о говорящем и адресате,
а итоговая проверка не допустила содержательных утверждений. Этот кандидат
не добавлен в меню; быстрота генерации не компенсирует ошибку чтения.
Использован GGUF Q4_K_M из `unsloth/Qwen3-4B-Instruct-2507-GGUF`, revision
`a06e946bb6b655725eafa393f4a9745d460374c9`, SHA-256
`3605803b982cb64aead44f6c1b2ae36e3acdb41d8e46c8a94c6533bc4c67e597`.
Загруженный для опыта файл удалён после остановки собственного сервера;
manifest и результаты сохранены для воспроизведения. Исходные модели сохранены.

Другой изученный кандидат, [LFM2.5-8B-A1B](https://huggingface.co/LiquidAI/LFM2.5-8B-A1B),
имеет 8.3B общих / 1.5B активных параметров, но русский отсутствует в заявленном

оснований рекомендовать её для русских документов без замера пока нет.

История пользователя и сохранённый выбор модели не изменялись. Дополнительные
веса исключены из Git и installer. Публичные файлы проверяются по точному размеру
и SHA-256 до установки. Контролируемые проверки кода прошли: 426 тестов,
58.62 секунды; они не доказывают отсутствие смысловых ошибок локальных моделей.

## Следующий шаг после сравнения моделей

После этих замеров реализована [контекстная сверка](contextual-answer-review.md).
Она сохраняет связный черновик, ограничивает автоматическую проверку двумя
вызовами и проверяет только точечные изменения. Замеры выше относятся к прежней
строгой цепочке и не описывают время нового пути.

Смена весов отдельно от цепочки не дала убедительной замены. Следующая проверяемая
гипотеза — сохранять связное объяснение из черновика и ограничить число его
исправлений. Точное присутствие цитаты проверяется программно; смысловой аудит
оценивает связи и выводы, сохраняя контекст говорящего, адресата и условий.
Отсутствие данных, противоречие источнику и технический отказ должны оставаться
разными результатами. Частично обоснованное объяснение нельзя представлять
полностью подтверждённым, но и ошибка одного предложения не должна стирать
остальные полезные предложения.

Сохранение неизменённых проверенных предложений уже реализовано. Нужен отдельный
эксперимент с более компактным аудитом связного ответа: текущая модель может
повторять собственную ошибку и на уровне отдельных утверждений. Уменьшение
числа вызовов даст выигрыш по времени, но само по себе не докажет качество.
Проверять его следует на разных задачах атрибуции, направленных отношений,
условий, намерений и недостатка данных, вместе с содержательностью итогового
ответа и полным временем. Новых правил
для отдельных имён, документов или сюжетов не добавлено.
